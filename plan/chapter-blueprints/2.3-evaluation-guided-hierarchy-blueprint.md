# 2.3 Evaluation-Guided Refinement 层级蓝图

### Parent paragraph 1

- Role: 定义评价信息回流的上位机制家族。
- Main claim: 当前候选先被评价，评价信息必须回流并产生下一候选；只对固定候选排序不属于本类。
- Evidence IDs: TAX-EVAL, TAX-SEL。
- Contrast: 父级只规定 `Assess → Update`，不预先把 `Update` 限定为 learned refiner 或数学求解器。
- Forbidden content: 不得把所有评价来源统称为 verifier，不得把固定候选 Selection 写成 Refinement。

### Parent paragraph 2

- Role: 区分两条评价到更新的子链。
- Main claim: 2.3.1 由 feedback-conditioned learned refiner 解释反馈；2.3.2 把评价写成显式目标或约束，并由 gradient、projection 或 local solver 直接计算下一点。
- Evidence IDs: TAX-EVAL, TAX-OBJ。
- Contrast: 二者都含评价，差别是评价怎样转化为更新量。
- Forbidden content: 不得把 Objective-Guided 与 Evaluation-Guided 继续平级，也不得抹去 learned update 与 numerical update 的差异。

### 2.3.1 Feedback-conditioned learned refinement

- Role: 定义 `f = Assess(o,a) → a' = Uθ(o,a,f)`。
- Main claim: Direct Verifier Feedback 直接计算 `V(o,a)`；World-Model-Mediated Outcome Feedback 先计算 `W(o,a)`，再由 `E` 将预测后果转为反馈。
- Evidence IDs: DV, SC, TAX-EVAL。
- Contrast: 两种来源共享 learned-update 子链；world model 本身只负责预测，`E∘W` 才形成后果评价。
- Case placement: DriveVer、CriticVLA 位于 direct-verifier 来源下；ReflectVLM、SC-VLA 位于 world-model-mediated 来源下。
- Forbidden content: 不得把反馈来源重新提升为与 2.3.2 平级的更新机制。

### 2.3.2 Objective-guided continuous refinement

- Role: 定义 `LocalSolve(J,𝒞) → projection → τ'`。
- Main claim: 显式目标或约束同样属于评价信息，但下一点由数学局部优化算子直接产生。
- Evidence IDs: TAX-OBJ。
- Contrast: learned verifier 或 differentiable world model 可以提供目标来源，但不改变 numerical update 子链；guided diffusion 使用 Generative + Objective Guidance 组合标签。
- Case placement: SafeBimanual、CHOMP、TrajOpt、UPN、UniAD、LAGO、Diffuser 与 Motion Planning Diffusion。
- Forbidden content: 不得因训练阶段存在 loss/reward/cost 就归入本类，不得把 CEM 群体分布更新归入单解局部优化。

### Boundary paragraph

- Role: 与 Selection、Adaptive Population 和 Environment-Feedback Replanning 分界。
- Main claim: 原候选 argmax 属于第 1 类；跨候选统计共同改变下一轮 proposal 属于第 3 类；真实执行后新观测属于第 5 类。
- Evidence IDs: TAX-SEL, TAX-OBJ。
- Contrast: 同一评价来源可服务多种规划操作，最终分类取决于实际更新数据流与一级计算拓扑。
- Forbidden content: 不得仅凭 verifier、world model、reward 或 cost 的模块名称归类。
