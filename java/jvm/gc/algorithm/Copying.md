# Copying（复制算法）

## 一句话
复制算法（Copying）是一类 GC 算法：将存活对象从一个空间复制/搬迁到另一个空间，并在复制完成后整体回收原空间。

## 严格定义
设堆空间被划分为源空间 $S$ 与目标空间 $T$（或更一般的多个分配区）。在一次回收中，算法将存活集合 $L$ 中的对象从 $S$ 搬迁到 $T$，并更新引用使其指向新位置。完成后，$S$ 可整体视为可用空间。复制算法的结果通常具有“空间连续性更强”的分配性质，但需要额外的目标空间或转移缓冲。

## 接口：数据 + 约束1
- 数据：
  - From/To 空间（或等价的分配区）
  - 转发表/转移标记（用于避免重复复制；实现定义）
- 输入：
  - 存活对象集合与对象图
- 输出：
  - 搬迁后的对象布局与更新后的引用
- 约束：
  - 搬迁需要更新引用（指针修正）；实现可使用不同屏障/读写路径完成该语义。

## 详细执行流程

### 1. 空间划分

复制算法将堆内存划分为两个大小相等的半区（或按比例划分）：

```
┌─────────────────────────────────────────────────────┐
│                    堆内存                            │
├─────────────────────┬───────────────────────────────┤
│    From 区（源空间）  │      To 区（目标空间）         │
│   - 当前分配区域      │      - 空闲区域               │
│   - 存放现有对象      │      - 等待接收存活对象        │
└─────────────────────┴───────────────────────────────┘
```

**在 JVM 新生代的实际应用（Eden + Survivor）：**

```
┌────────────────────────────────────────────────────────────┐
│                      新生代（Young Generation）             │
├──────────────────────────┬──────────────┬──────────────────┤
│       Eden 区（80%）      │ Survivor0（10%）│ Survivor1（10%）│
│   - 新对象分配区          │  (From/To轮换)  │  (From/To轮换)  │
└──────────────────────────┴──────────────┴──────────────────┘
```

### 2. 标记阶段：如何判断对象是否是垃圾

**步骤 2.1：枚举 GC Roots**

从以下位置收集根对象引用：
- 虚拟机栈（栈帧中的局部变量表）引用的对象
- 方法区中类静态属性引用的对象
- 方法区中常量引用的对象
- 本地方法栈中 JNI 引用的对象
- JVM 内部引用（如基本数据类型的 Class 对象、异常对象等）
- 被同步锁（synchronized）持有的对象

**步骤 2.2：从 GC Roots 出发进行可达性分析**

```
GC Roots
   │
   ├──→ 对象A ──→ 对象B ──→ 对象C    ← 这条链上的对象都是存活的
   │
   ├──→ 对象D ──→ 对象E              ← 这条链上的对象都是存活的
   │
   └──→ 对象F                        ← 存活

       对象G ──→ 对象H                ← 无法从 GC Roots 到达，是垃圾
       对象I                          ← 无法从 GC Roots 到达，是垃圾
```

**判定规则：**
- **存活对象**：从 GC Roots 出发，通过引用链可达的对象
- **垃圾对象**：从 GC Roots 出发，无法到达的对象

### 3. 复制阶段：从哪复制到哪

**场景1：标准两半区复制**

```
执行前：
┌─────────────────────┬───────────────────────────────┐
│      From 区         │            To 区（空）         │
│  [A][B][C][D][E]     │                               │
│   ↑存活  ↑垃圾 ↑存活  │                               │
└─────────────────────┴───────────────────────────────┘

步骤：
1. 从 GC Roots 遍历，找到存活对象 A、C、E
2. 将 A、C、E 按顺序复制到 To 区
3. 更新所有指向旧地址的引用为新地址
4. 清空整个 From 区
5. From/To 角色互换

执行后：
┌─────────────────────┬───────────────────────────────┐
│   To 区（原From，空） │      From 区（原To）          │
│        （空）         │  [A'][C'][E']                 │
│                      │   连续排列，无碎片             │
└─────────────────────┴───────────────────────────────┘
```

**场景2：JVM 新生代 Minor GC 流程**

```
触发条件：Eden 区满

第1次 Minor GC：
┌──────────────────┬─────────────┬─────────────┐
│     Eden 区       │ Survivor0   │ Survivor1   │
│ [A][B][C][D][E]  │   （空）     │   （空）     │
│  ↑活 ↑死 ↑活      │             │             │
└──────────────────┴─────────────┴─────────────┘
                         ↓
1. 标记 Eden 中存活对象（A、C）
2. 将存活对象复制到 Survivor0（设为 To 区）
3. 对象年龄 +1（A.age=1, C.age=1）
4. 清空 Eden
                         ↓
┌──────────────────┬─────────────┬─────────────┐
│     Eden 区       │ Survivor0   │ Survivor1   │
│     （空）        │ [A][C]      │   （空）     │
│                  │  age=1       │             │
└──────────────────┴─────────────┴─────────────┘


第2次 Minor GC：
┌──────────────────┬─────────────┬─────────────┐
│     Eden 区       │ Survivor0   │ Survivor1   │
│ [F][G][H]        │ [A][C]      │   （空）     │
│  ↑活 ↑死          │  ↑活        │             │
└──────────────────┴─────────────┴─────────────┘
                         ↓
1. 标记 Eden + Survivor0 中存活对象（F、A）
2. 将存活对象复制到 Survivor1（此时 S1 是 To 区）
3. 对象年龄 +1（F.age=1, A.age=2）
4. 清空 Eden + Survivor0
5. S0/S1 角色互换
                         ↓
┌──────────────────┬─────────────┬─────────────┐
│     Eden 区       │ Survivor0   │ Survivor1   │
│     （空）        │   （空）     │ [A][F]      │
│                  │   下次是To   │ age=2,1     │
└──────────────────┴─────────────┴─────────────┘


对象晋升到老年代：
- 当对象年龄达到阈值（默认15），晋升到老年代
- 或 Survivor 空间不足时，直接晋升

┌──────────────────┬─────────────┬─────────────┐
│     Eden 区       │ Survivor    │   老年代     │
│                  │             │  [A]        │
│                  │             │  age≥15     │
└──────────────────┴─────────────┴─────────────┘
```

### 3.1 关键问题：Survivor 放不下怎么办？

**问题场景**：Eden 区 80%，Survivor 只有 10%，如果存活对象超过 10% 怎么办？

```
假设：新生代 100MB
- Eden: 80MB
- S0: 10MB  
- S1: 10MB

极端情况：Eden 中有 20MB 存活对象，但 Survivor 只有 10MB！

┌────────────────────────────┬──────────┬──────────┐
│         Eden（80MB）        │ S0(10MB) │ S1(10MB) │
│  存活对象: 20MB             │   空      │   空     │
│  放不进 10MB 的 Survivor！   │          │          │
└────────────────────────────┴──────────┴──────────┘
```

**JVM 的解决方案：分配担保（Handle Promotion）**

```
                    Minor GC 开始
                          │
                          ▼
              ┌───────────────────────────┐
              │  标记 Eden + From Survivor │
              │  中的所有存活对象           │
              └───────────────────────────┘
                          │
                          ▼
              ┌───────────────────────────┐
              │  尝试复制到 To Survivor    │
              └───────────────────────────┘
                          │
            ┌─────────────┴─────────────┐
            │                           │
      Survivor 放得下            Survivor 放不下
            │                           │
            ▼                           ▼
    ┌─────────────────┐      ┌─────────────────────────┐
    │ 正常复制到       │      │ 溢出部分直接晋升到老年代 │
    │ To Survivor     │      │ （分配担保）             │
    └─────────────────┘      └─────────────────────────┘

具体流程：
┌────────────────────────────┬──────────┬──────────┬────────────────┐
│         Eden（80MB）        │ S0(空)   │ S1(10MB) │    老年代       │
│  存活: A B C D E (共20MB)   │          │          │                │
└────────────────────────────┴──────────┴──────────┴────────────────┘
                                   ↓
1. 按顺序复制存活对象到 S1
2. A(4MB) → S1 ✓  剩余6MB
3. B(4MB) → S1 ✓  剩余2MB  
4. C(4MB) → S1 ✗  放不下！→ 直接晋升到老年代
5. D(4MB) → 老年代 ✓
6. E(4MB) → 老年代 ✓
                                   ↓
┌────────────────────────────┬──────────┬──────────┬────────────────┐
│         Eden（空）          │ S0(空)   │ S1(8MB)  │    老年代       │
│                            │          │ [A][B]   │   [C][D][E]    │
│                            │          │ age=1    │   直接晋升      │
└────────────────────────────┴──────────┴──────────┴────────────────┘
```

**担保失败怎么办？**

```
如果老年代也放不下溢出对象：

                    Survivor 放不下
                          │
                          ▼
              ┌───────────────────────────┐
              │  尝试晋升到老年代          │
              └───────────────────────────┘
                          │
            ┌─────────────┴─────────────┐
            │                           │
      老年代放得下                老年代也放不下
            │                           │
            ▼                           ▼
    ┌─────────────────┐      ┌─────────────────────────┐
    │ 晋升成功         │      │ 担保失败！               │
    │ Minor GC 完成    │      │ 触发 Full GC            │
    └─────────────────┘      └─────────────────────────┘
                                        │
                                        ▼
                             ┌─────────────────────────┐
                             │ Full GC 清理老年代后     │
                             │ 重新尝试分配/晋升        │
                             └─────────────────────────┘
                                        │
                              ┌─────────┴─────────┐
                              │                   │
                          还是放不下            放得下了
                              │                   │
                              ▼                   ▼
                      ┌─────────────┐      ┌─────────────┐
                      │ OOM 异常！   │      │  GC 完成     │
                      └─────────────┘      └─────────────┘
```

**为什么 8:1:1 的比例是安全的？**

```
基于"弱分代假说"的经验数据：
┌─────────────────────────────────────────────────────────────┐
│  绝大多数对象都是"朝生夕死"的                                 │
│  - 典型应用中，Eden 区 90%-98% 的对象在下次 GC 时已死亡       │
│  - 存活对象通常只有 2%-10%                                   │
│                                                             │
│  80MB Eden 的存活对象：                                      │
│  - 最好情况：80MB × 2% = 1.6MB  << 10MB Survivor ✓          │
│  - 典型情况：80MB × 5% = 4MB    <  10MB Survivor ✓          │
│  - 较差情况：80MB × 10% = 8MB   <  10MB Survivor ✓          │
│  - 极端情况：超过 10MB → 触发分配担保，晋升到老年代           │
└─────────────────────────────────────────────────────────────┘

这就是为什么 JVM 选择 8:1:1 而不是 5:1:1 或 9:0.5:0.5：
- 8:1:1 在大多数情况下 Survivor 足够用
- 同时最大化了 Eden 区（新对象分配效率）
- 极端情况有担保机制兜底
```

### 4. 引用更新

复制完成后，需要更新所有指向旧地址的引用：

```
复制前：                          复制后：
栈帧变量 ref1 ──→ [对象A@0x100]   栈帧变量 ref1 ──→ [对象A@0x500]
对象B.field  ──→ [对象A@0x100]   对象B.field  ──→ [对象A@0x500]
                                 （所有引用都更新为新地址）
```

**实现方式：转发指针（Forwarding Pointer）**
1. 复制对象到新位置
2. 在原对象头中存储转发地址
3. 遍历所有引用，通过转发地址更新为新位置
