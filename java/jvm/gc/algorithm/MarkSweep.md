# MarkSweep（标记-清除）

## 一句话
标记-清除（Mark-Sweep）是一类 GC 算法：先标记存活对象，再回收未标记对象占用的空间。

## 严格定义
在对象引用图上，标记阶段计算存活集合 $L \subseteq O$（通常由可达性分析得到），清除阶段回收 $O \setminus L$ 对应的堆空间。该算法不要求在回收后移动存活对象，因此可能导致堆空间碎片化（fragmentation），后续分配可能依赖空闲链表等结构。

## 接口：数据 + 约束
- 数据：
  - 标记位/标记集合（实现定义）
  - 空闲空间管理结构（实现定义）
- 输入：
  - Roots 与引用图（见 [../mechanism/ReachabilityAnalysis.md](../mechanism/ReachabilityAnalysis.md)）
- 输出：
  - 回收后的空闲空间集合（可能非连续）
- 约束：
  - 是否并行/并发、是否增量化、以及标记位存储位置等属于收集器实现细节。

## 详细执行流程

### 1. 空间结构

标记-清除算法直接在原有堆空间上操作，不需要额外的复制空间：

```
┌───────────────────────────────────────────────────────────┐
│                        堆内存                              │
│  [A][B][C][D][E][F][G][H][I][J]                            │
│   分配指针 →                                               │
│   空闲链表头 → null（初始状态）                              │
└───────────────────────────────────────────────────────────┘
```

### 2. 标记阶段（Mark）：如何判断对象是否是垃圾

**步骤 2.1：枚举 GC Roots**

从以下位置收集根对象引用：
- 虚拟机栈（栈帧中的局部变量表）引用的对象
- 方法区中类静态属性引用的对象
- 方法区中常量引用的对象
- 本地方法栈中 JNI 引用的对象
- JVM 内部引用（基本数据类型的 Class 对象、异常对象等）
- 被同步锁（synchronized）持有的对象

**步骤 2.2：从 GC Roots 进行深度优先/广度优先遍历**

```
初始状态：所有对象标记位 = 0（未标记）

GC Roots
   │
   ├──→ 对象A（标记位设为1）──→ 对象C（标记位设为1）
   │
   ├──→ 对象D（标记位设为1）
   │
   └──→ 对象F（标记位设为1）──→ 对象G（标记位设为1）

未被访问到的对象：B、E、H、I、J（标记位仍为0，是垃圾）
```

**步骤 2.3：三色标记法（并发收集器使用）**

```
┌─────────────────────────────────────────────────────────┐
│  白色：尚未访问的对象（初始状态，GC结束后仍为白色则回收）     │
│  灰色：已访问但其引用的对象尚未全部访问                      │
│  黑色：已访问且其所有引用对象都已访问（确定存活）             │
└─────────────────────────────────────────────────────────┘

遍历过程：
1. 初始：所有对象为白色，GC Roots 直接引用的对象变为灰色
2. 从灰色对象取出一个，将其引用的白色对象变为灰色，自身变为黑色
3. 重复步骤2，直到没有灰色对象
4. 剩余的白色对象即为垃圾

示例：
   [白A] [白B] [白C] [白D]       ← 初始
      ↓
   [灰A] [白B] [白C] [白D]       ← A 被 GC Root 引用，变灰
      ↓
   [黑A] [灰B] [白C] [白D]       ← 访问 A，A的引用B变灰，A变黑
      ↓
   [黑A] [黑B] [灰C] [白D]       ← 访问 B，B的引用C变灰，B变黑
      ↓
   [黑A] [黑B] [黑C] [白D]       ← 访问 C，C无引用，C变黑
      ↓
   结束：D仍为白色，是垃圾
```

### 3. 清除阶段（Sweep）：回收垃圾对象

**步骤 3.1：遍历堆空间，回收未标记对象**

```
标记后的堆状态：
┌───────────────────────────────────────────────────────────┐
│  [A✓][B✗][C✓][D✓][E✗][F✓][G✓][H✗][I✗][J✗]                 │
│   ✓=存活  ✗=垃圾                                           │
└───────────────────────────────────────────────────────────┘

清除过程：
1. 从堆起始地址开始遍历每个对象
2. 检查对象标记位：
   - 标记位=1：存活对象，重置标记位为0（为下次GC准备）
   - 标记位=0：垃圾对象，将其空间加入空闲链表

清除后的堆状态：
┌───────────────────────────────────────────────────────────┐
│  [A][空][C][D][空][F][G][空][空][空]                        │
│      ↑       ↑       ↑   ↑   ↑                            │
│      └───────┴───────┴───┴───┘                            │
│              空闲链表连接                                   │
└───────────────────────────────────────────────────────────┘
```

**步骤 3.2：空闲链表管理**

```
空闲链表结构：
┌─────┐    ┌─────┐    ┌─────┐    ┌─────┐    ┌─────┐
│ B空 │───→│ E空 │───→│ H空 │───→│ I空 │───→│ J空 │───→ null
│32B  │    │64B  │    │32B  │    │48B  │    │32B  │
└─────┘    └─────┘    └─────┘    └─────┘    └─────┘

分配策略：
- First-Fit：找到第一个足够大的空闲块
- Best-Fit：找到最接近所需大小的空闲块
- Worst-Fit：找到最大的空闲块
```

### 4. 完整执行流程图

```
┌─────────────────────────────────────────────────────────────┐
│                    Mark-Sweep 完整流程                       │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
              ┌─────────────────────────┐
              │  1. Stop-The-World      │
              │     暂停所有应用线程     │
              └─────────────────────────┘
                            │
                            ▼
              ┌─────────────────────────┐
              │  2. 枚举 GC Roots       │
              │  - 扫描虚拟机栈         │
              │  - 扫描方法区静态变量    │
              │  - 扫描 JNI 引用        │
              └─────────────────────────┘
                            │
                            ▼
              ┌─────────────────────────┐
              │  3. 标记阶段            │
              │  从 Roots 遍历引用链    │
              │  标记所有可达对象        │
              └─────────────────────────┘
                            │
                            ▼
              ┌─────────────────────────┐
              │  4. 清除阶段            │
              │  遍历堆中所有对象        │
              │  回收未标记对象到空闲链表 │
              └─────────────────────────┘
                            │
                            ▼
              ┌─────────────────────────┐
              │  5. 恢复应用线程         │
              └─────────────────────────┘
```

### 5. 内存碎片问题

```
多次 GC 后的堆状态（产生碎片）：

┌─────────────────────────────────────────────────────────────┐
│ [对象][空32B][对象][空16B][对象][空64B][对象][空8B][对象]     │
└─────────────────────────────────────────────────────────────┘

问题：需要分配一个 100B 的对象
- 空闲总量：32+16+64+8 = 120B > 100B
- 但最大连续空间只有 64B < 100B
- 结果：分配失败！触发 Full GC 或 OOM

这就是为什么老年代通常使用 Mark-Compact 而不是 Mark-Sweep
```
