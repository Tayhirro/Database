# MarkCompact（标记-整理）

## 一句话
标记-整理（Mark-Compact）是一类 GC 算法：先标记存活对象，再通过搬迁/压缩将存活对象整理到一端，释放连续空间。

## 严格定义
标记阶段计算存活集合 $L$；整理阶段为 $L$ 中对象计算新位置并搬迁对象，最终使得空闲空间在堆中形成更连续的区间。与 Mark-Sweep 相比，Mark-Compact 通过搬迁降低碎片化，但引入对象移动与引用更新成本。

## 接口：数据 + 约束
- 数据：
  - 标记信息（存活集合）
  - 搬迁计划/转发表（实现定义）
- 输入：
  - Roots 与引用图
- 输出：
  - 更连续的可用空间与更新后的引用
- 约束：
  - 整理阶段通常需要全局一致性边界或等价机制以保证引用更新的安全性（机制依收集器实现）。

## 详细执行流程

### 1. 空间结构

标记-整理算法在原有堆空间上操作，通过移动对象消除碎片：

```
┌───────────────────────────────────────────────────────────┐
│                        堆内存（老年代）                     │
│  [A][空][B][空][C][空][D][空][E]     ← GC前，有碎片        │
│  [A][B][C][D][E][────空闲────]       ← GC后，连续空间      │
└───────────────────────────────────────────────────────────┘
```

### 2. 标记阶段（Mark）：如何判断对象是否是垃圾

**步骤 2.1：枚举 GC Roots**

从以下位置收集根对象引用：
- 虚拟机栈（栈帧中的局部变量表）引用的对象
- 方法区中类静态属性引用的对象
- 方法区中常量引用的对象
- 本地方法栈中 JNI 引用的对象
- JVM 内部引用（基本数据类型的 Class 对象、异常对象等）
- 被同步锁（synchronized）持有的对象
- **跨代引用**：年轻代对象引用的老年代对象（通过 Remember Set/Card Table）

**步骤 2.2：从 GC Roots 进行可达性分析**

```
GC Roots
   │
   ├──→ 对象A ──→ 对象C        ← 存活
   │
   ├──→ 对象E ──→ 对象F        ← 存活
   │
   └──→ 对象H                  ← 存活

未被访问：B、D、G、I（垃圾）

标记后状态：
┌─────────────────────────────────────────────────────────────┐
│ [A✓][B✗][C✓][D✗][E✓][F✓][G✗][H✓][I✗]                        │
│  ✓=存活（标记位=1）  ✗=垃圾（标记位=0）                        │
└─────────────────────────────────────────────────────────────┘
```

### 3. 整理阶段（Compact）：从哪移动到哪

**核心思想**：将所有存活对象向一端移动，清理边界外的空间

**步骤 3.1：计算新地址（第一次遍历）**

```
原始位置：
地址:    0x100  0x120  0x140  0x160  0x180  0x200  0x220  0x240  0x260
对象:    [A✓]   [B✗]   [C✓]   [D✗]   [E✓]   [F✓]   [G✗]   [H✓]   [I✗]
大小:    32B    32B    32B    32B    32B    32B    32B    32B    32B

计算新地址（只给存活对象分配）：
对象A: 原地址 0x100 → 新地址 0x100（第1个存活对象，放在起始位置）
对象C: 原地址 0x140 → 新地址 0x120（第2个存活对象，紧跟A后面）
对象E: 原地址 0x180 → 新地址 0x140（第3个存活对象，紧跟C后面）
对象F: 原地址 0x200 → 新地址 0x160（第4个存活对象，紧跟E后面）
对象H: 原地址 0x240 → 新地址 0x180（第5个存活对象，紧跟F后面）

转发表：
┌────────┬────────┐
│ 原地址  │ 新地址  │
├────────┼────────┤
│ 0x100  │ 0x100  │ ← A 不需要移动
│ 0x140  │ 0x120  │ ← C 向前移动
│ 0x180  │ 0x140  │ ← E 向前移动
│ 0x200  │ 0x160  │ ← F 向前移动
│ 0x240  │ 0x180  │ ← H 向前移动
└────────┴────────┘
```

**步骤 3.2：更新引用（第二次遍历）**

```
更新前：
栈帧变量 ref1 ──→ 0x140（指向C的旧地址）
对象A.field   ──→ 0x140（指向C的旧地址）
对象E.field   ──→ 0x200（指向F的旧地址）

更新过程：
1. 遍历所有 GC Roots 和存活对象的引用字段
2. 对于每个引用，查转发表获取新地址
3. 更新引用为新地址

更新后：
栈帧变量 ref1 ──→ 0x120（指向C的新地址）
对象A.field   ──→ 0x120（指向C的新地址）
对象E.field   ──→ 0x160（指向F的新地址）
```

**步骤 3.3：移动对象（第三次遍历）**

```
移动前：
┌─────────────────────────────────────────────────────────────┐
│ [A]   [B]   [C]   [D]   [E]   [F]   [G]   [H]   [I]         │
│ 0x100 0x120 0x140 0x160 0x180 0x200 0x220 0x240 0x260       │
└─────────────────────────────────────────────────────────────┘

移动过程（按地址顺序，避免覆盖）：
1. A (0x100→0x100): 不移动
2. C (0x140→0x120): 复制到 0x120
3. E (0x180→0x140): 复制到 0x140
4. F (0x200→0x160): 复制到 0x160
5. H (0x240→0x180): 复制到 0x180

移动后：
┌─────────────────────────────────────────────────────────────┐
│ [A]   [C]   [E]   [F]   [H]   [─────空闲空间─────]          │
│ 0x100 0x120 0x140 0x160 0x180  0x1A0 ─────────→ 0x280       │
│         连续的存活对象         │      连续的空闲空间          │
└─────────────────────────────────────────────────────────────┘
```

### 5. 与 Mark-Sweep 的对比

```
┌────────────────┬─────────────────────┬─────────────────────┐
│     特性        │    Mark-Sweep       │    Mark-Compact     │
├────────────────┼─────────────────────┼─────────────────────┤
│  对象移动       │        不移动        │        移动         │
│  内存碎片       │        有碎片        │        无碎片       │
│  分配效率       │   需要空闲链表查找    │   指针碰撞，O(1)    │
│  GC 耗时        │        较短          │        较长        │
│  堆遍历次数     │        2次           │        3次         │
│  适用场景       │   对象存活率高时      │   老年代回收       │
└────────────────┴─────────────────────┴─────────────────────┘

为什么老年代使用 Mark-Compact：
1. 老年代对象存活率高，复制算法浪费空间
2. Mark-Sweep 会产生碎片，长期运行后大对象无法分配
3. Mark-Compact 虽然慢，但保证内存连续，分配高效
```
