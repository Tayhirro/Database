# GenerationalGC（分代收集）

## 一句话
分代收集（Generational GC）是基于对象“短命更常见”的经验假设，将堆划分为不同代并对各代采用不同回收策略的 GC 组织方式。

## 严格定义
设堆被划分为若干代集合 $\{G_0, G_1, \dots\}$（常见二代划分为 Young/Old）。分代收集在回收某一代时，利用跨代引用跟踪结构（例如记忆集/卡表）限制扫描范围，使得对年轻代的回收可以在不全堆扫描的前提下完成，从而改变一次回收的工作范围边界（语义级）。

分代是组织方式而非单一算法：各代内部可使用 Mark-Sweep、Copying、Mark-Compact 等不同算法组合（见 [MarkSweep.md](MarkSweep.md)、[Copying.md](Copying.md)、[MarkCompact.md](MarkCompact.md)）。

## 接口：数据 + 约束
- 数据：
  - 代划分与边界（实现定义）
  - 跨代引⽤跟踪结构（见 [../mechanism/CardTable.md](../mechanism/CardTable.md)、[../mechanism/RememberedSet.md](../mechanism/RememberedSet.md)）
- 输入：
  - 分配与晋升（promotion）导致的对象代际变化（实现定义）
- 输出：
  - 分代回收后的空间变化与对象移动结果（若存在）
- 约束：
  - “代”的具体数量、边界与晋升策略依收集器实现与参数而定。

## 详细执行流程

### 1. 堆内存分代结构

```
┌─────────────────────────────────────────────────────────────────────┐
│                            JVM 堆内存                                │
├───────────────────────────────────────────┬─────────────────────────┤
│              新生代（Young Generation）     │   老年代（Old Gen）     │
│                    约 1/3 堆               │      约 2/3 堆          │
├──────────────────┬─────────┬──────────────┼─────────────────────────┤
│   Eden 区（80%） │ S0(10%) │  S1(10%)     │                         │
│   新对象分配区    │Survivor │ Survivor    │    长期存活对象          │
└──────────────────┴─────────┴──────────────┴─────────────────────────┘

默认比例参数：
- -XX:NewRatio=2        → 老年代:新生代 = 2:1
- -XX:SurvivorRatio=8   → Eden:S0:S1 = 8:1:1
```

### 2. 对象分配流程

```
                    新对象创建
                        │
                        ▼
            ┌───────────────────────┐
            │ 尝试在 Eden 区分配     │
            └───────────────────────┘
                        │
           ┌────────────┴────────────┐
           │                         │
      Eden 有空间              Eden 空间不足
           │                         │
           ▼                         ▼
    ┌─────────────┐         ┌─────────────────┐
    │ 分配成功     │         │ 触发 Minor GC    │
    └─────────────┘         └─────────────────┘
                                     │
                                     ▼
                            ┌─────────────────┐
                            │ GC 后重新尝试    │
                            │ 在 Eden 分配    │
                            └─────────────────┘

大对象直接进入老年代：
- -XX:PretenureSizeThreshold=3145728  → 大于3MB直接分配到老年代
```

### 3. Minor GC 详细流程（新生代回收）

**触发条件**：Eden 区空间不足

**步骤 3.1：枚举 GC Roots**

```
GC Roots 来源：
├── 虚拟机栈中引用的对象
├── 方法区中静态属性引用的对象
├── 方法区中常量引用的对象
├── 本地方法栈中 JNI 引用的对象
└── 老年代对新生代的引用（通过 Card Table 快速定位）
    │
    └── Card Table 机制：
        ┌─────────────────────────────────────────┐
        │ 老年代被划分为 512B 的卡片（Card）        │
        │ 每个卡片有一个标记位                     │
        │ 当老年代对象引用新生代对象时，卡片标脏    │
        │ Minor GC 只扫描脏卡片，避免全堆扫描      │
        └─────────────────────────────────────────┘
```

**步骤 3.2：标记存活对象**

```
从 GC Roots 出发，标记 Eden 区和 From Survivor 区的存活对象

Eden 区：                     From Survivor（S0）：
┌──────────────────────┐     ┌─────────────┐
│ [A✓][B✗][C✓][D✗][E✗] │     │ [X✓][Y✗]    │
│  ↑可达 ↑不可达        │     │  ↑可达      │
└──────────────────────┘     └─────────────┘

存活对象：A、C（来自Eden）、X（来自S0）
垃圾对象：B、D、E（来自Eden）、Y（来自S0）
```

**步骤 3.3：复制存活对象到 To Survivor**

```
复制前：
┌────────────────────┬─────────────┬─────────────┐
│       Eden          │    S0(From) │   S1(To)    │
│ [A][B][C][D][E]     │   [X][Y]    │    空        │
└────────────────────┴─────────────┴─────────────┘

复制过程：
1. 将存活对象（A、C、X）复制到 S1（To Survivor）
2. 对象年龄 +1
3. 检查年龄是否达到晋升阈值

复制后：
┌────────────────────┬─────────────┬─────────────┐
│       Eden          │    S0(From) │   S1(To)    │
│       空            │      空      │ [A][C][X]  │
│                    │             │ age+1       │
└────────────────────┴─────────────┴─────────────┘

4. S0 和 S1 角色互换（下次 GC 时 S1 变成 From）
```

**步骤 3.4：对象晋升到老年代**

```
晋升条件（满足任一即晋升）：

1. 年龄达到阈值（-XX:MaxTenuringThreshold=15）
   ┌─────────────────────────────────────────────┐
   │ 对象在 Survivor 区每熬过一次 Minor GC，年龄+1 │
   │ 当年龄 ≥ 15 时，晋升到老年代                  │
   └─────────────────────────────────────────────┘

2. 动态年龄判断
   ┌─────────────────────────────────────────────┐
   │ 如果 Survivor 区中相同年龄对象总大小 >        │
   │ Survivor 空间的一半，则该年龄及以上对象直接晋升 │
   └─────────────────────────────────────────────┘

3. Survivor 空间不足
   ┌─────────────────────────────────────────────┐
   │ 存活对象太多，Survivor 放不下时              │
   │ 部分对象直接晋升到老年代                     │
   └─────────────────────────────────────────────┘

晋升流程图：
                    存活对象
                        │
          ┌─────────────┴─────────────┐
          │                           │
    年龄 < 阈值                  年龄 ≥ 阈值
          │                           │
          ▼                           ▼
┌──────────────────┐        ┌──────────────────┐
│ 复制到 To Survivor│        │  晋升到老年代     │
│     年龄 +1       │        │                  │
└──────────────────┘        └──────────────────┘
          │
          ▼
   Survivor 空间足够？
          │
    ┌─────┴─────┐
   是           否
    │            │
    ▼            ▼
  正常复制    溢出对象晋升到老年代
```

### 4. Major GC / Full GC 详细流程

**触发条件**：
- 老年代空间不足
- 方法区（元空间）空间不足
- 调用 System.gc()
- Minor GC 后晋升对象大于老年代剩余空间
- 担保失败

**执行流程**：

```
┌─────────────────────────────────────────────────────────────┐
│                      Full GC 执行流程                        │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
              ┌─────────────────────────┐
              │  1. Stop-The-World      │
              │     停止所有应用线程     │
              └─────────────────────────┘
                            │
                            ▼
              ┌─────────────────────────┐
              │  2. 标记阶段            │
              │  - 枚举全部 GC Roots    │
              │  - 标记整个堆的存活对象  │
              │  （新生代 + 老年代）     │
              └─────────────────────────┘
                            │
                            ▼
              ┌─────────────────────────┐
              │  3. 清理/整理阶段        │
              │  - 新生代：复制算法      │
              │  - 老年代：标记-整理算法 │
              └─────────────────────────┘
                            │
                            ▼
              ┌─────────────────────────┐
              │  4. 恢复应用线程         │
              └─────────────────────────┘

Full GC 耗时通常是 Minor GC 的 10 倍以上！
```

### 5. 跨代引用处理

**问题**：Minor GC 时如何知道老年代哪些对象引用了新生代？

```
问题场景：
┌─────────────────────┬─────────────────────┐
│      新生代          │        老年代        │
│                     │                     │
│    ┌───┐           │    ┌───┐            │
│    │ A │ ←─────────┼────│ X │            │
│    └───┘           │    └───┘            │
│                     │       │             │
│                     │       ▼             │
│                     │    ┌───┐            │
│                     │    │ Y │            │
│                     │    └───┘            │
└─────────────────────┴─────────────────────┘

如果不处理跨代引用，A 会被误认为是垃圾（无法从新生代 Roots 到达）
```

**解决方案：Card Table（卡表）**

```
Card Table 结构：
┌─────────────────────────────────────────────────────────┐
│                      老年代                              │
│ ┌─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┐      │
│ │Card0│Card1│Card2│Card3│Card4│Card5│Card6│Card7│      │
│ │512B │512B │512B │512B │512B │512B │512B │512B │      │
│ │     │ [X] │     │     │     │     │ [Y] │     │      │
│ │     │  │  │     │     │     │     │     │     │      │
│ └─────┴──┼──┴─────┴─────┴─────┴─────┴─────┴─────┘      │
└──────────┼──────────────────────────────────────────────┘
           │ 引用
           ▼
┌─────────────────────────────────────────────────────────┐
│ [A]                新生代                                │
└─────────────────────────────────────────────────────────┘

Card Table（字节数组，每个卡片1字节）：
┌───┬───┬───┬───┬───┬───┬───┬───┐
│ 0 │ 1 │ 0 │ 0 │ 0 │ 0 │ 0 │ 0 │  ← 1 表示脏卡（有跨代引用）
└───┴───┴───┴───┴───┴───┴───┴───┘
      ↑
   Card1 有对象引用了新生代，标记为脏

Minor GC 时：
1. 扫描 Card Table，找到所有脏卡
2. 只扫描脏卡对应的老年代区域
3. 将脏卡中引用新生代的对象加入 GC Roots
4. 避免扫描整个老年代
```

### 6. 空间分配担保

```
Minor GC 前的担保检查：

                    Minor GC 触发
                          │
                          ▼
        ┌──────────────────────────────────────┐
        │ 老年代剩余空间 > 新生代所有对象总大小？ │
        └──────────────────────────────────────┘
                          │
              ┌───────────┴───────────┐
              是                       否
              │                        │
              ▼                        ▼
       ┌─────────────┐    ┌─────────────────────────────┐
       │ 执行 Minor GC│    │ HandlePromotionFailure开启？│
       └─────────────┘    └─────────────────────────────┘
                                       │
                           ┌───────────┴───────────┐
                           是                       否
                           │                        │
                           ▼                        ▼
              ┌─────────────────────────┐    ┌─────────────┐
              │ 老年代剩余 > 历次晋升平均？│    │ 执行 Full GC │
              └─────────────────────────┘    └─────────────┘
                           │
               ┌───────────┴───────────┐
               是                       否
               │                        │
               ▼                        ▼
        ┌─────────────┐          ┌─────────────┐
        │ 执行 Minor GC│          │ 执行 Full GC │
        │ （可能担保失败）│          └─────────────┘
        └─────────────┘
               │
         担保失败？
               │
         ┌─────┴─────┐
         是           否
         │            │
         ▼            ▼
   执行 Full GC   Minor GC 完成
```

### 7. 分代收集策略总结

```
┌─────────────────────────────────────────────────────────────────┐
│                        分代收集策略                              │
├─────────────────┬───────────────────────────────────────────────┤
│     新生代       │                    老年代                      │
├─────────────────┼───────────────────────────────────────────────┤
│ 使用算法：复制算法│ 使用算法：标记-整理 / 标记-清除               │
├─────────────────┼───────────────────────────────────────────────┤
│ 回收频率：频繁    │ 回收频率：较少                                │
├─────────────────┼───────────────────────────────────────────────┤
│ 回收速度：快     │ 回收速度：慢                                  │
├─────────────────┼───────────────────────────────────────────────┤
│ 对象特点：        │ 对象特点：                                   │
│ - 大量对象朝生夕死│ - 存活率高                                   │
│ - 存活率低（<10%）│ - 生命周期长                                 │
├─────────────────┼───────────────────────────────────────────────┤
│ 为什么用复制：    │ 为什么用标记-整理：                           │
│ - 存活对象少，    │ - 存活对象多，复制代价大                      │
│   复制代价小     │ - 需要避免碎片                                │
│ - 只需 10% 空间  │ - 不需要额外空间                              │
│   作为 Survivor  │                                              │
└─────────────────┴───────────────────────────────────────────────┘
```
