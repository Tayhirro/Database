# 沟通

通过弱关系桥接不同圈层，占据结构洞位置，获取非冗余信息。
具体来说下面可实现从难到易
- 给予对方给对方提供有帮助的内容，而不只是单纯请求 --**低姿态但不低价值的连接能力**
- 通过可见产出降低信任成本，判断值得交流 --**可见产出能力**
	- 非领域如何交流
- 降低沟通成本，表述清楚自己的内容以及产出 
- 后续反馈



# 调研
首先需要对调研的方向，问题进行**问题拆解**
## 问题类型
调研问题的本质，是在一个不确定领域里，明确自己到底想消除哪一种不确定性。
- 现状/结构型问题
	- 这个领域有什么？怎么分？现在发展到哪了？
- 机制解释型问题
	- 为什么会这样？这个现象是怎么产生的？中间链路是什么？
	- 多agent安全会和多agent架构有关 （可以给出初步猜想，思路）
- 评价/比较型问题
	- 哪个更好？差异在哪里？优缺点是什么？
- 可行性/决策型问题
	- 这个方向能不能做？值不值得做？适不适合当前条件？
本质6点：
- **边界问题**：它是什么，什么不算它。
	- 比如：什么算 LLM 多智能体系统
- **结构问题**：它由什么组成，可以怎么分。
	- LLM 多 Agent 可以按 Chain、Debate、Router、Shared Memory、Tool-based Workflow 分类；也可以按角色分工、通信拓扑、记忆机制、工具权限分类
	- 某种算法的具体结构
- **机制问题**：它为什么这样运作，各部分如何相互作用。  【靠后期】
	- 比如：为什么 Agent 间通信会导致信息污染传播？为什么共享记忆会导致长期污染？为什么 Router 会引入编排攻击面？这里解决的是“因果链条”。
- **条件问题**：它在什么条件下成立，什么时候不成立。     【早期】
- **评价问题**：它好不好，风险大不大，怎么比较。               
	- 比如：哪种架构更高效？哪种架构更容易传播攻击？
- **干预问题**：我如何改变它，如何攻击、防御、优化或设计。【后期】
	- 比如：能否设计跨 Agent 信息污染攻击？能否设计安全感知 Router？能否做工具权限隔离？能否构建 benchmark？这类问题进入方法设计和实验验证。
- **证据问题**：我凭什么这么判断。 每一类问题都要问的底层约束
