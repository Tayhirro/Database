# RoPE长上下文扩展方法

导航：[RoPE.md](./RoPE.md) | [位置编码](../README.md)

**核心问题**：RoPE在预训练长度（如32k）内表现良好，但如何外推到更长的序列（如128k+）？

---

## 核心挑战：RoPE的外推瓶颈

### 问题本质

RoPE通过旋转角度编码位置：角度 = 位置p × 频率ω

当序列长度L增加时：
- **短序列**（L=2k）：旋转角度小，位置区分度好
- **长序列**（L=128k）：旋转角度累积过大，出现**相位混乱**

**症状**：
1. 远距离token的注意力分数衰减
2. 相对位置关系难以稳定保持
3. 模型在训练长度之外的序列上性能下降

---

## 解决方案1：调整Base Frequency（ABF类方法）

### 核心思想

**增大RoPE的base值（θ），降低旋转频率**

公式变化：
```
原：ω_i = 10000^(-2i/d)  
新：ω_i = B^(-2i/d)，其中 B >> 10000（如1,000,000）
```

**直观理解**：
- Base增大 → 频率ω减小 → 同样位置p下旋转角度更小
- 长序列时不会"转得太疯"，相位关系更可控

### 技术分类与详细原理

#### 1. NTK-aware（神经正切核感知）

**核心问题**：ABF全局增大base会"一刀切"地降低所有维度的频率，导致短距离精细度丢失。

**解决思路**：**区别对待不同维度**——高频维度（对应短距离）少缩放，低频维度（对应长距离）多缩放。

**直观理解**：
- 像渐进多焦点眼镜：上半部分（低频/长距离）高度缩放，下半部分（高频/短距离）轻微缩放
- 既看得清远处的山（长距离），又看得清眼前的字（短距离）

**数学公式**：
```python
# NTK-aware频率计算
# 高频维度（i小）：保持原频率或轻微缩放
# 低频维度（i大）：大幅缩放

alpha = 缩放因子（如8，表示目标长度是训练长度的8倍）

for i in range(dim//2):
    if i < dim * 0.75:  # 前75%为高频维度
        # 高频：几乎不缩放
        freq_i = 1.0 / (base ** (2*i/dim))
    else:
        # 低频：线性插值到更大的base
        freq_i = 1.0 / ((base * alpha) ** (2*i/dim))
```

**效果**：
- ✅ 高频维度保持敏感，短距离精度不丢失
- ✅ 低频维度充分缩放，长距离稳定性增强
- ⚠️ 实现稍复杂，需要确定分界点

---

#### 2. Dynamic NTK（动态NTK）

**核心问题**：NTK-aware使用固定的scale因子（如8倍），但对于不同长度的输入（如8k、32k、128k），固定scale可能不是最优的。

**解决思路**：**根据实际输入长度动态计算base**，短序列用小base，长序列用大base，完全自适应。

**直观理解**：
- 像自动对焦相机：拍近处自动调近焦，拍远处自动调远焦
- 不需要手动选择scale，模型自己根据输入长度"智能选择"

**数学公式**（关键！）：

当输入序列长度 **L ≤ L_train**（训练长度）时：
```python
base' = base  # 保持不变
```

当输入序列长度 **L > L_train** 时：
```python
# Step 1: 计算长度缩放因子
scale = L / L_train

# Step 2: 动态调整base（核心公式）
base' = base × (scale)^(d/(d-2))

# 其中：
# base = 10000（原始值）
# d = head_dim（注意力头维度，如64、128）
# L = 当前输入序列长度
# L_train = 训练时的最大长度（如4096）
```

**具体例子**（假设d=128，base=10000，L_train=4096）：

| 输入长度 L | scale = L/4096 | 计算过程 | 新的 base' |
|-----------|---------------|---------|-----------|
| 4096 | 1 | 10000 × 1^(128/126) | **10000**（不变）|
| 8192 | 2 | 10000 × 2^(1.016) ≈ 10000 × 2.015 | **20150** |
| 32768 | 8 | 10000 × 8^(1.016) ≈ 10000 × 8.12 | **81200** |
| 131072 | 32 | 10000 × 32^(1.016) ≈ 10000 × 33.5 | **335000** |

**代码实现**：
```python
def get_dynamic_ntk_base(seq_len, train_len=4096, base=10000, dim=128):
    """
    Dynamic NTK: 根据序列长度动态调整RoPE base
    """
    if seq_len <= train_len:
        # 短序列：保持原base
        return base
    
    # 长序列：动态计算
    scale = seq_len / train_len
    # 核心公式
    new_base = base * (scale ** (dim / (dim - 2)))
    
    return new_base

# 使用示例
for L in [4096, 8192, 32768, 131072]:
    base_dynamic = get_dynamic_ntk_base(L)
    print(f"序列长度 {L:6d} -> base = {base_dynamic:.0f}")
```

**效果**：
- ✅ 完全自适应，无需手动调参
- ✅ 短序列（≤训练长度）保持原有精度
- ✅ 长序列自动增大base，防止旋转过快
- ⚠️ 每次推理都需要根据输入长度重新计算频率

---

#### 3. 方法对比

| 方法 | 核心思想 | Base值 | 优点 | 缺点 | 适用场景 |
|------|---------|--------|------|------|---------|
| **ABF** | 全局增大base | 固定（如1e6） | 简单有效 | 短距离可能过度 | 统一处理长序列 |
| **NTK-aware** | 维度差异化缩放 | 固定，但不同维度不同 | 兼顾短长距离 | 需确定分界点 | 需要精细控制 |
| **Dynamic NTK** | 根据输入长度动态调整 | 动态变化 | 完全自适应 | 每次都要计算 | 输入长度变化大 |

---

### 效果
- **优点**：无需额外训练或少量训练即可外推
- **代价**：可能损失短距离精细度（高频信息被"压平"）

## 解决方案2：精细化频率缩放（YaRN）

### 核心思想

**不对所有频率做统一缩放，而是分段/渐进式处理**

ABF的问题：
- 全局降低频率 → 短距离精度下降

YaRN的改进：
- **低频部分**（对应长距离）：显著缩放，增强长距离稳定性
- **高频部分**（对应短距离）：轻微缩放，保持局部精度
- **温度缩放**：对注意力logits进行温度调节，平衡远近关系

### 关键机制

```
频率分组：不同维度组应用不同缩放因子
温度调节：softmax前除以温度系数，控制分布锐度
```

### 效果
- 兼顾短距离精度和长距离外推
- 训练成本较低，推理时直接应用

|------|---------|----------------|------|

| **训练需求** | 预训练长度内 | 少量微调或无需训练 | 少量微调 |
| **实现复杂度** | 简单 | 简单 | 中等 |

## 实现要点

### 修改RoPE的base参数

```python
# 原始RoPE
freqs = 1.0 / (theta ** (torch.arange(0, dim, 2) / dim))

# ABF：增大theta
theta_new = 1_000_000  # 从10000增大到1e6
freqs = 1.0 / (theta_new ** (torch.arange(0, dim, 2) / dim))
```

### YaRN的关键：频率分组缩放

```python
# 对不同维度组应用不同缩放
# 低频组（长距离）：大幅缩放
# 高频组（短距离）：轻微缩放
scale_factors = get_scale_factors(dim, scale=8, beta=32)
freqs_scaled = freqs * scale_factors
```
