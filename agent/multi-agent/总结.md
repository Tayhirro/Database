## 一、核心判断

多智能体系统（Multi-Agent System, MAS）的设计必要性应从任务结构、信息结构与质量控制结构共同判断。经典 agent 文献将智能体概括为具备自主性、反应性、主动性和社会能力的软件实体；MAS 进一步研究多个自治实体之间的交互、协作、协调、竞争与组织机制 [Wooldridge & Jennings, 1995; Jennings et al., 1998]。



1. **任务能明显并行**：目标可分解为依赖较弱的子问题，子结果能够通过聚合、归约、流水线或编排层整合。
2. **不同子任务需要不同专业视角**：子任务依赖不同知识、工具、评价标准或角色责任，适合用专用 agent 承担。 编程更简单
3. **鲁棒性**  ：由于行为不确定 需要有鲁棒性需求


4. **可扩展性** ：系统规模变大时，可以继续增加 agent，而不是把所有功能塞进一个巨大的中央控制器
5. **领域要求**
	1. **存在对手、协作者或局部信息**：系统中不同主体拥有不同信息、目标、约束或收益函数，需要协商、博弈、建模他者行为或处理分布式状态。
	2. **需要互审、投票、博弈或故障隔离**：输出质量依赖独立检查、辩论、裁判、冗余验证、异常隔离或多路径求解。

6. **用于研究智能本身** 很多智能行为不是单个体内部产生的，而是在交互中产生的，比如协作、竞争、谈判、让行、博弈、群体决策。研究多智能体可以帮助理解“社会性智能”。

总的来说：
1：多智能体的交互可以带来更多探索，效果更好
- 搜索的本质是压缩，从庞大的语料库中提炼见解，为了把巨大的信息空间分散探索，然后各自压缩成小块高价值信息，再交给主代理综合
2：多agent可以避免污染主llm的上下文
3：领域本身要求 or 多agent交互产生智能

**认知循环陷阱**：智能体陷入死循环 —— 反复执行同一个失败操作，却意识不到自己在原地打转。AutoGPT 因此声名狼藉：进入无限循环是它最常被提及的缺陷。目前没有通用的系统性解决方案，大多数「反循环」机制靠的是特定任务的手工调参。

**上下文窗口限制**：模型的「工作记忆」是有限的。一次长时间科研会话可能产生十万个以上的词元（token），超出窗口范围的早期信息便永久消失。层级编排能缓解这个问题，但仍难以真正实现跨会话的「研究记忆」。

**新颖性评估**：AI 产出的研究成果，如何判断它是否真正新颖？引用量预测受社会因素干扰，语义相似度又无法区分「新颖」和「偏僻冷门」。目前能做到客观验证的，只有像 FunSearch 那样用程序输出量化衡量的极少数领域。

**可重现性危机**：同样的系统、同样的任务，每次运行结果可能大相径庭。基准测试上的性能数字，标准差动辄达到 5% 至 15%。如何在随机性和严谨性之间找到平衡，目前尚无定论。
**安全与伦理**：能自主设计化学合成方案的系统，同样可能被引向危险化合物。这不只是「加一个过滤器」就能解决的工程问题，而是一个根本性的架构矛盾 —— 对益处有用的能力，往往和对害处有用的能力难以分离。

**成本与可及性**：解决一个 SWE-bench 任务的 API 费用，约在 5 至 50 美元之间；完整的科研流程则可能消耗数百至数千美元。最强大的基础模型仍是专有的、昂贵的。如果自主科研能力只属于资源雄厚的机构，那么它加速的，也可能是科研不平等而非科研本身。

## 三、设计动因

### 3.1 任务分解与并行执行

复杂任务往往包含多个依赖关系较弱的子问题。MAS 通过任务划分、角色分派和结果聚合，将整体目标拆解为可并行推进的局部目标。Stone 与 Veloso 对 DPS 与 MAS 的区分说明，分解、分派和综合是多主体系统的重要基础；当子任务之间可以弱耦合执行时，MAS 能够降低单个 agent 的上下文压力，并提升探索宽度 [Stone & Veloso, 2000]。
在 LLM agent 系统中，这一点尤其重要。单个 agent 同时承担规划、检索、工具选择、执行、错误恢复和结果验证时，上下文窗口会被任务状态、工具说明、中间轨迹和环境反馈快速占用。多个 agent 分担子问题后，每个 agent 可维护较窄的局部上下文，编排层负责依赖关系、状态合并和最终决策。

### 3.2 专业化与异质能力组织

MAS 的第二个动因来自专业化。不同子任务可能需要不同知识背景、工具权限、评价指标和输出格式。通过 profile、role、memory、tool set 与 policy 的差异化配置，系统可以将“产品经理、架构师、工程师、测试者、审查者、检索者、规划者”等角色转化为可调度的 agent。

ChatDev 将软件开发组织为由专用 agent 参与的设计、编码、测试等阶段，并通过语言通信连接各阶段 [Qian et al., 2024]。MetaGPT 将标准作业流程（SOP）编码到多 agent 协作中，通过装配线式分工、角色专业化和中间结果验证来减少级联幻觉并提升软件工程输出的一致性 [Hong et al., 2024]。这些工作说明，MAS 在软件工程中的价值集中于工程流程组织、角色责任分配和中间产物校验，单纯增加生成样本数量不足以解释其收益。

### 3.3 环境本身需要多agent

当环境中存在多个主体、局部可见状态、冲突目标或资源竞争时，系统需要处理“谁知道什么、谁能做什么、谁的目标与系统目标一致或冲突”等问题。Shoham 与 Leyton-Brown 的 MAS 基础理论涵盖非合作博弈、社会选择、机制设计、拍卖和联盟博弈，说明多主体设置适合刻画异质信息、策略行为和激励约束 [Shoham & Leyton-Brown, 2009]。

在工程实现中，这类需求对应任务分派、权限边界、资源竞标、异常责任定位、对抗性测试、红队审查和人机协同。若任务本身包含协作者或对手，MAS 可以把这些关系显式化，使协商、验证、反驳和让步成为系统结构的一部分。

### 3.4 互审、辩论与故障隔离

LLM 系统的一个核心风险是单一路径推理会产生自洽但错误的结论。多 agent 互审、辩论、投票和裁判机制通过引入独立视角缓解该问题。Du 等人的 multiagent debate 工作表明，多个模型实例围绕答案与推理过程进行多轮辩论，可提升若干任务中的数学推理、策略推理与事实有效性 [Du et al., 2023]。Liang 等人的 MAD 框架进一步强调，多主体辩论能够促进发散思考，但裁判公平性和辩论强度需要被控制 [Liang et al., 2024]。

故障隔离也是同一逻辑的工程化表达。将规划、执行、验证、诊断和修复拆成不同 agent 后，错误可被限制在较小责任边界内；编排层可以基于日志、状态和质量信号触发重试、回滚、仲裁或人工介入。对于高风险任务，MAS 的价值体现在可审计、可回放、可定位和可替换的系统结构上。

### 3.5 可治理、可观测与企业落地

MAS 进入真实生产环境后，需要处理权限、审计、状态管理、失败恢复、成本控制和质量评估等系统问题。统一编排层可将任务规划、策略约束、执行控制、状态与知识管理、质量运维纳入同一治理框架。AutoGen 等框架展示了可定制、可对话、可结合工具和人类输入的多 agent 交互基础设施 [Wu et al., 2023]；面向企业采用的 MAS 编排框架进一步强调协议、治理、观测和运维能力对可靠部署的重要性 [Adimulam et al., 2026]。

因此，MAS 的设计动因可以概括为：当任务复杂性超出单个 agent 的上下文、工具、专业能力、交互建模或质量验证边界时，通过多主体分工、通信、编排与治理机制获得系统级收益。

# 安全

## 分类方式
- 攻击对象 / 攻击操作 / 攻击目标 / 实现方法
- 对记忆进行攻击
	- Memory Poisoning = 攻击长期记忆/RAG；操作是写入或污染；目标是破坏真实性/完整性；方法是注入恶意文档， chunk、后门触发样本
	- Privacy Leakage = 攻击长期记忆/RAG；操作是读取或外泄；目标是破坏隐私/保密性；方法是越狱查询、RAG 数据抽取、嵌入反演。
	- Memory Misuse = 攻击短期记忆/上下文；操作是多轮写入上下文并操纵上下文状态；目标是**绕过安全对齐**；方法是多轮越狱、分布式触发器、多轮后门。
- 对大脑进行攻击 
	- Jailbreak = 攻击的是模型的安全对齐机制；操作是向模型输入流中注入越狱载荷，也就是构造一段会干扰安全拒答的 prompt，让模型重新解释任务边界。；目标是让模型面对一个本来应该拒绝的恶意请求时，不再拒绝；优化对抗后缀
	- Prompt Injection = 直接攻击指令遵循机制 / 指令优先级，指令边界（可能影响安全机制）；操作是把恶意指令嵌入用户输入、网页、RAG 文档或工具返回内容中；目标是**覆盖任务**，**绕过安全对齐**；方法是手工注入、梯度优化注入、多模态扰动、间接提示注入。
	- 后门
- 对工具进行攻击 ： 主体对象是工具，目标是引导llm在调用工具时出错
	- Tool Manipulation = 攻击的是 Agent 的**工具调用链路**；攻击目标是诱导 Agent 执行恶意或敏感工具行为；操作手段是干扰工具规划、选择、参数生成、执行或结果解释；攻击方法包括（第一类）越狱、提示注入、（第二类）工具注入、命令伪造和（第三类）第三方 API 输出操作 
	- Tool Abuse = 攻击的是 Agent **工具能力的使用边界**；攻击目标是利用 Agent 的工具执行能力对外部系统、用户资源或现实环境造成危害；操作手段是诱导或构造任务，使 Agent 合法调用工具完成恶意目的；攻击方法包括恶意任务驱动、后门触发、拒答机制绕过后的工具滥用等；其特点是工具调用流程本身可能没有被篡改，但工具被用于不该做的事情。
		- Tool-enabled Misuse 攻击者把 Agent 当作攻击器使用 Agent 的工具权限与任务边界
		- Tool-triggered Backdoor  特定触发器让 Agent 调用工具做坏事 Agent 模型或策略内部
		- Tool-context Alignment Failure  聊天模型会拒绝，但接入工具后不再拒绝   工具场景下的安全对齐

| 攻击方法                | 攻击目标                           | 操作手段                           | 特点                         |
| ------------------- | ------------------------------ | ------------------------------ | -------------------------- |
| Jailbreak           | 绕过 Agent 的安全限制，让其调用敏感工具或泄露信息   | 通过越狱提示诱导模型忽略安全规则               | 表面攻击大脑，实际落点是工具调用行为         |
| Prompt Injection    | 覆盖原始任务指令，使 Agent 调用错误工具或执行无关动作 | 在网页、文档、用户输入、RAG 内容或工具返回中嵌入恶意指令 | 容易发生在外部数据进入 Agent 的场景      |
| Tool Injection      | 污染 Agent 可用工具集合，让其选择恶意工具       | 注册或暴露伪装成正常功能的恶意工具              | 很像 MCP 场景下的“恶意工具混入工具列表”    |
| Command Forgery     | 伪造合法工具调用命令，诱导系统执行或推断敏感信息       | 生成符合工具调用格式的伪造命令或参数             | 攻击点在“工具调用格式”和“命令合法性判断”     |
| Direct Manipulation | 操纵第三方 API 或工具返回结果，误导 Agent 决策  | 注入恶意返回内容，或删除、篡改关键返回信息          | 攻击者不一定控制 Agent 输入，而是污染工具输出 |

## 小结

多智能体架构和业务强绑定，因为属于架构的agent分工，编排通常需要根据业务的需求特化，而对于多智能体系统安全，他可以归因于智能体架构，大模型本身能力，具体业务场景，具体来说，他本质是大模型本身的**不可靠性**（加上在智能体化之后带来的不可靠性），在多智能体通信、记忆、工具调用和权限分配等**架构机制**中被放大，并最终在具体业务场景中表现为**可观测的安全后果**

 > 目的：解决工具与reasoning平衡问题，整合llm的对于使用工具如search，code等的能力 应对 探索性质/多样化问题
 > 
 >  对比传统解决问题
 >  
 >  **多模型答案聚合 / 多模型协作**：multi-agent debate、MoA、Symbolic-MoE
 >  >MoA 具体是 layered architecture，每一层有多个 LLM agents，后一层 agent 读取前一层所有 agent 的输出再生成新答案，它的多样性主要来自“不同 LLM”。 Symbolic-MoE 则进一步做“路由”：它根据题目所需技能选择相关专家 LLM，比如数学题选代数/几何强的专家，生物医学题选相关专家，再由 aggregator 综合答案。
 >  **单模型多次采样 / 自聚合**：Self-MoA 和 GSA 
 >  >Self-MOA用同一个最强 LLM 多次生成、再聚合，反而经常优于混合不同 LLM,GSA，也就是 Generative Self-Aggregation，则是让同一个 LLM 先生成多个 diverse responses，然后让模型基于这些样本生成一个综合答案；它强调不依赖模型去“判别哪个答案最好”，而利用模型的生成能力来合成更好答案
 >  **同一 LLM 内部的多 agent / 多策略推理时缩放**：SETS、GSA、部分 DEI 思路、以及 TUMIX
 >  >

>[! info] 思想
>特点
>-	 多agent
>>	深入单研究内部的多agent互相分工
>	
>-	实际闭环验证
>>	实验和真实值绑定
>

>-	复杂度定义转接
>
>本质：
>- 把科研过程形式化为“可验证反馈驱动的假设—实验—修正闭环”
>- **哲学**
> 	- **本体论**（研究对象）：  
> 		- 科研过程本身，即 hypothesis、method、experiment、result、failure、human feedback、claim 共同构成的研究状态空间。 这个研究状态空间强调两个核心属性：  
> 			- 可验证：实验、代码、数据、指标、日志需要和真实结果绑定。  
> 			- 可反馈迭代：系统能够根据实验结果、失败信息、人类反馈和历史记忆进行多轮修正。  
> 	- **认识论**（如何获得可靠知识）：  
> 		- 外部知识直接注入：可靠知识来自外部证据约束，包括真实实验、代码执行、数据结果、运行日志、指标变化、引用检查和人类反馈。  
> 		- 反馈+修正 llm内部知识    
> 		- 不断更新判断
> 		- 失败内容具有可提取价值
> 	 
> 	- **方法论 / 科学哲学**：  
> 		- 整个流程接近真实科学方法：提出假设 → 设计实验 → 执行验证 → 观察结果 → 诊断失败 → 修正假设。  
> 		- 科研价值来自可追踪、可验证、可复现的证据链。  
> 		- 多 agent 将科研中的不同认知角色显式化，使提出、质疑、实验、分析和审稿等环节相互约束。
> - 创新点总结  
> 	- 从无约束文本生成走向 evidence-grounded claim generation。  
> 	- 从单 agent 自洽推理（上下文造成的连续认知偏差）走向多 agent 认知制衡。  
> 	- 从失败终止走向失败诊断与修正。  
> 	- 从单次运行走向跨运行记忆与科研经验积累。

## TaskCraft 
>[! info] 思考
>原子任务反向构建 
>depth，width扩展任务 depth用search agent检索超集避免循环依赖

自动生成 Agentic 任务，用于构造更丰富的 Agent 训练和评测场景。
- 引入 TaskCraft，一个自动化工作流，用于生成难度可扩展、多工具且可验证的 Agentic 任务及其执行轨迹
方法：
- 把真实工具可访问的网页/PDF/图片等外部内容，先构造成“单工具可验证原子任务”
- depth/width 两种可控扩展机制，把它们递归组合成多跳、多工具、难度可扩展的 agentic 任务，并且在生成过程中天然保留答案、工具调用轨迹和验证信号
	- （工具能访问）真实内容抽取事实-->事实包装（必须调用工具才能答的原子任务）-->原子任务扩展成依赖链或并行组合
		- 构建数据
		- 工具调用+抽取事实，让 LLM 推断“这个答案 a 和工具输入 index 之间是什么关系 R”；最后生成自然语言问题 q
		- **纵向多跳扩展**。这是把一个 1-hop 原子任务变成 2-hop、3-hop……任务。核心机制是：把原任务里的某个关键输入 index 替换成另一个更上层、更宽泛、但能唯一定位原 index 的 superset index 
			- 伪多跳和答案泄露 strict superset verification 和 information leakage verification
			- 超集 避免循环依赖
		- ![[Pasted image 20260613061202.png]]
		- **横向组合扩展**。width 是“并行子问题组合”。它把两个或多个原子任务合成一个更大的问题，让 agent 必须拆成多个子任务分别求解，再综合答案。例如“TaskCraft 用什么方法扩展原子任务，并且它产生的数据集规模和难度变化是什么？”这类任务的难点不是深链路，而是 decomposition：agent 要知道这个大问题其实包含多个独立槽位。
		- ![[Pasted image 20260613061216.png]]
