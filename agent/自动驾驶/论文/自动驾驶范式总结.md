# 自动驾驶范式总结

> [!summary] 核心判断
> 先按“是否引入语言/大模型”分两大类最清楚：**不含 LLM/VLM 的传统与学习式自动驾驶**坐一桌，**含 VLM/LLM/VLA 的大模型自动驾驶**单开一桌。第二层再按模型在系统中的作用区分：理解、规划、动作、多任务、agent、协同。

## 1. 总体层级

```text
自动驾驶范式
├─ A. 不含 LLM/VLM 的自动驾驶
│  ├─ A1. 传统模块化：感知 -> 跟踪 -> 预测 -> 规划 -> 控制
│  ├─ A2. 学习式中间表示：BEV / occupancy / vector map / learned prediction
│  ├─ A3. Planning-oriented 统一栈：统一模型做多任务，最终服务规划
│  ├─ A4. 端到端 Vision-Action：视觉/状态 -> trajectory / waypoints / control
│  └─ A5. 世界模型 / 生成式驾驶：预测未来场景，辅助规划和仿真
│
└─ B. 含 VLM/LLM/VLA 的大模型自动驾驶
   ├─ B1. VLM/LLM as Reasoner：场景理解、问答、解释、风险判断
   ├─ B2. Prompt-based / Tool-based Driving Planner：用 prompt、工具、检索做高层规划
   ├─ B3. Language-conditioned Planner：语言条件下输出候选轨迹或 waypoints
   ├─ B4. VLA Driving Model：Vision + Language + State -> Action / Trajectory / Waypoints
   ├─ B5. Multi-task VLA / Driving Foundation Model：一个模型支持感知、预测、问答、规划、动作
   └─ B6. Agentic / Cooperative Driving：记忆、工具、反思、通信、多车协商
```

- **没有语言/LLM/VLM**：传统栈、BEV、occupancy、planning-oriented、端到端 VA、世界模型。
- **有语言/LLM/VLM，并参与规划**：prompt planner / language-conditioned planner。 


- **有语言/LLM/VLM，但只说不做**：VLM/LLM reasoner。
- **有语言/LLM/VLM，并输出可执行动作**：VLA。
- **还能做很多下游任务**：multi-task VLA / driving foundation model。
- **还有记忆、工具、反思、通信、协商**：agentic driving model。


## 论文分类

### DriveLM：Graph VQA 驱动的 reasoning-to-action VLA

| 对象                          | 分类                                                | 理由                                                                                                 |
| --------------------------- | ------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| DriveLM Task / DriveLM Data | **B1. VLM/LLM Reasoner**                          | 核心贡献是 Graph VQA 数据、任务和评价方式，用问答图组织感知、预测、规划推理。                                                       |
| DriveLM-Agent baseline      | **B5. Multi-task VLA / Driving Foundation Model** | 它把 Perception、Prediction、Planning、Behavior、Motion 串成统一多任务推理链。                                      |
| DriveLM-Agent 的 Motion 输出   | **B4. VLA Driving Model**                         | 最后会生成 ego future trajectory / waypoints，trajectory 被 tokenization 后作为语言模型可生成的 motion/action token。 |

它的推理链大致是：

```text
图像 / 多视角场景
        -> Graph VQA
        -> P1 Perception：关键目标和场景理解
        -> P2 Prediction：其他交通参与者未来运动
        -> P3 Planning：ego 可选安全动作
        -> B Behavior：驾驶行为描述
        -> M Motion：ego future trajectory / waypoints
```

```text
主分类：B5. Multi-task VLA / Driving Foundation Model
副分类：B1. VLM/LLM Reasoner
动作分支：B4. VLA Driving Model
补充标签：Graph VQA、open-loop trajectory generation、trajectory tokenization
```

### SimLingo：closed-loop driving-first 的多任务 VLA

SimLingo它的主任务就是 closed-loop driving。它是用 VLM backbone 同时做驾驶、语言理解和 language-action alignment。

| 对象               | 分类                                                | 理由                                                                                      |
| ---------------- | ------------------------------------------------- | --------------------------------------------------------------------------------------- |
| SimLingo 整体      | **B5. Multi-task VLA / Driving Foundation Model** | 同一个模型同时支持 closed-loop driving、VQA/commentary、language-action alignment、action dreaming。 |
| SimLingo 的驾驶动作分支 | **B4. VLA Driving Model**                         | 输入视觉、ego state、导航/语言条件，输出可执行的 speed waypoints 和 path waypoints。                         |
| SimLingo 的语言理解分支 | **B1. VLM/LLM Reasoner**                          | 可以生成 commentary、回答 VQA 问题，解释当前驾驶场景和下一步行为。                                               |

它的整体链路是：

```text
Camera images
+ ego speed
+ target point / navigation command / language prompt
        -> VLM backbone
        -> language prediction / commentary / VQA
        -> temporal speed waypoints + geometric path waypoints
        -> PID controller
        -> steering / acceleration
```

SimLingo 的 waypoint 输出分成两类：

- **temporal speed waypoints**：按时间采样，用来估计目标速度，再由 PID 生成 acceleration。
- **geometric path waypoints**：按空间距离采样，用来估计目标转向角，再由 PID 生成 steering。

因此它更接近：

```text
Vision + Language + State -> Waypoints -> Controller
```

```

SimLingo 还提出 Action Dreaming，用于检查模型是否真的听语言指令。同一个视觉场景下，给不同的语言动作指令，模型应该生成不同的未来动作或 waypoint。这一点让它比普通 VQA 更接近 VLA 的 language-action alignment。

```text
主分类：B5. Multi-task VLA / Driving Foundation Model
动作分支：B4. VLA Driving Model
副分类：B1. VLM/LLM Reasoner
不是：B6. Agentic / Cooperative Driving
补充标签：closed-loop driving、language-action alignment、action dreaming、waypoint prediction、PID control
```



## 2. A 类：不含 LLM/VLM 的自动驾驶

### A1. 传统模块化

最经典的工程范式：

```text
定位/地图 -> 感知 -> 跟踪 -> 预测 -> 行为决策 -> 运动规划 -> 控制
```

典型中间接口是检测框、车道线、目标轨迹、预测轨迹、规划轨迹。优点是可解释、可调试、可插拔；缺点是模块间误差级联，固定接口会损失不确定性和交互信息。

### A2. 学习式中间表示

这类还不算“大模型驾驶”，但已经用深度学习把传统手工接口换成更统一的表示，例如：

- **BEV 表示**：把多视角图像投到鸟瞰图空间。
- **Occupancy 表示**：预测空间中哪些区域被占据，以及未来 occupancy rollout。
- **Vectorized map / agent representation**：用向量化车道、边界、agent motion 表示场景。
- **Learned prediction**：用网络预测其他交通参与者未来轨迹。

它仍然服务于传统的预测和规划，只是中间表示更神经网络化。

### A3. Planning-oriented 统一栈

这类是传统模块化和端到端之间的折中。它保留 tracking、mapping、motion forecasting、occupancy、planning 等任务，但放进一个统一模型里联合训练，最终目标是自车规划质量。

代表：

- **UniAD**：统一 tracking、mapping、motion forecasting、occupancy prediction 和 planning，最终输出 ego future waypoints。
- **VAD**：用 vectorized scene representation 表示地图和动态 agent，再做规划。

它的关键词不是“语言”，而是 **planning-oriented**：所有中间任务都服务于最后的 ego planning。

### A4. 端到端 Vision-Action

端到端 Vision-Action 不引入语言，核心是：

```text
camera / lidar / BEV / ego state / route command
        -> neural policy
        -> steering / throttle / brake 或 trajectory / waypoints
```

它又可以分成：

- **强端到端**：直接输出 steering、throttle、brake。
- **弱端到端 / E2E planning**：输出 future trajectory / waypoints，再交给控制器。
- **带辅助任务的端到端**：训练时做检测、分割、深度、地图、预测等辅助监督，推理时仍输出规划结果。

注意：**输出 waypoints 本身不等于 VLA**。没有语言条件时，它只是 Vision-Action 或 end-to-end planning。

### A5. 世界模型 / 生成式驾驶

世界模型学习：

```text
history observation + ego action + map/context -> future scene evolution
```

它可以生成 future video、future BEV、occupancy rollout、agent trajectory distribution，或者在 latent space 里做未来展开。用途是辅助规划、生成长尾训练数据、做反事实仿真。

代表：

- **DriveDreamer**：真实驾驶数据驱动的世界模型和可控场景生成。
- **GAIA-1**：生成式驾驶世界模型。

世界模型本身不一定含 LLM/VLM。若它再和 VLA 结合，例如 DriveWorld-VLA，就归入 B 类的大模型驾驶。

## 3. B 类：含 VLM/LLM/VLA 的大模型自动驾驶
- VQA 问答
- LLM指导-下游路线回归



### B0. 价值定位：补高层认知，不替代控制栈

LLM/VLM 进入自动驾驶后，最稳的定位是补传统驾驶栈较弱的高层语义能力。做场景理解、风险解释、规则推理、意图表达、多车协商和经验复用，再把结果交给可验证的 planner 或 controller 落成轨迹与控制。

- 常识：大模型的涌现能力--使得他拥有人类的常识     
	- 学到“人类觉得合理、可解释、舒适、守规矩”的行为先验  【**泛化能力**】
		- RL 与 搜索 方法 依赖人工设计的目标函数  
	- 可以使人直接参与对话
- 推理
- 时延问题
- 



- **语义理解与解释**：把复杂交通场景转成“谁在影响谁、风险在哪里、为什么要让行”的可读推理链。
- **长尾场景处理**：面对稀有交互、异常行为或规则冲突时，利用常识、交通规则、历史经验和反思结果给出高层判断。
- **多车协同与自然语言 V2V**：用语言表达意图、请求、让行策略和盲区信息，支持车辆之间协商路权。
- **低带宽语义通信**：像 LangCoop 一样，把图像、点云或中间特征压缩成自然语言包，降低通信压力，也方便异构车辆理解。
- **记忆与持续学习**：通过 memory / reflection 保存失败案例和有效经验，让下一次相似场景的决策不只依赖当前观测。

但边界也要说清楚：LLM/VLM 的推理延迟、幻觉、几何精度和安全验证都还不足以支撑底层实时控制。因此更合理的系统形态是“LLM 做高层认知与协商，传统/神经 planner 做轨迹，控制器做实时执行”。

### B1. VLM/LLM as Reasoner：只理解、解释、问答

这类模型把 VLM/LLM 当作驾驶场景理解器或解释器，输入可以是图像、BEV、对象列表、轨迹、地图、文本指令，输出通常是：

- 场景描述。
- 风险解释。
- 交通规则判断。
- Graph VQA。
- 高层驾驶建议。

代表：

- **DriveLM 的 GVQA 数据/中间推理部分**：用 Graph VQA 组织感知、预测、规划问题。
- **DriveVLM**：用 VLM 做场景描述、场景分析和层级规划。

单看这类 reasoner 输出，还不能直接叫 VLA，因为它主要输出文本或高层判断，不一定输出可执行动作。注意：**DriveLM-Agent 另有 Motion 输出分支，因此 DriveLM-Agent 不能只归到 B1**。

### B2. Prompt-based / Tool-based Driving Planner

这类重点在 **prompt** 或 **工具调用**。常见做法是先把环境转成结构化文本，再让 LLM/VLM 通过 prompt 做推理：

```text
scene tokens / object list / map / traffic rules
        -> prompt / CoT / retrieval / tool call
        -> high-level decision 或 candidate plan
```

如果它调用检测器、预测器、地图查询器、碰撞检查器、规则库，就更接近 tool-based planner。它通常不直接控制车辆，而是输出让行、变道、减速、等待、绕行等高层策略，或者给下游 planner 一个约束。

### B3. Language-conditioned Planner：语言条件规划

这一类已经把语言接进规划，但输出通常还是 trajectory / waypoints，且常有下游 planner 或 controller：

```text
vision / BEV / ego state + language instruction
        -> planner
        -> trajectory / waypoints
        -> controller
```

它和普通 Vision-Action 的区别是有语言条件；和纯 VLA 的区别是，它未必把动作生成统一进同一个大模型，可能只是“语言增强的 planner”。

代表：

- **VLP**：Vision-Language Planning，语言增强视觉规划。
- **LMDrive**：多视角传感器 + 自然语言指令，用于闭环驾驶。

### B4. VLA Driving Model：语言进入动作空间

VLA 的最小定义是：

```text
Vision + Language + State -> Action
```

自动驾驶里的 action 可以是：

- 离散 action token：keep lane、yield、change lane。
- 连续控制：steering、throttle、brake。
- 未来轨迹：ego trajectory。
- 航点：waypoints。

所以，**VLA 和普通 waypoint planner 的区别不在输出是不是 waypoint，而在输入和建模目标是否包含 language/action 对齐**。

代表：

- **DriveLM-Agent 的 motion stage**：Graph VQA 推理后生成 ego future trajectory / waypoints。
- **CoVLA**：构建 vision-language-action 数据集。
- **OpenDriveVLA**：2D/3D 视觉 token、ego state 和语言指令生成 grounded driving actions。
- **Alpamayo-R1**：reasoning VLA，把因果推理和轨迹规划结合。

### B5. Multi-task VLA / Driving Foundation Model

你说的“VLA 还支持一堆下游任务输出”，更适合放在这一类。它不是单纯：

```text
vision + language -> action
```

而是：

```text
vision + language + state
        -> perception / prediction / QA / explanation / planning / action
```

它可以输出检测、地图、occupancy、风险判断、问答、文本解释、trajectory、waypoints、control。学术上可以叫：

- **Multi-task VLA**。
- **Generalist Driving Model**。
- **Unified Driving Foundation Model**。
- **Task-generalized VLA for autonomous driving**。

判断标准：如果论文强调“一个模型统一多种驾驶任务”，它就比普通 VLA 更像 driving foundation model。

代表：

- **DriveLM-Agent**：统一 Perception、Prediction、Planning、Behavior、Motion 的 Graph VQA 多任务链，最后可输出 future trajectory / waypoints。
- **SimLingo**：统一 closed-loop driving、VQA/commentary 和 language-action alignment。

### B6. Agentic / Cooperative Driving

Agentic driving 不只是一个模型输入输出映射，而是一个驾驶智能体系统：

```text
观察环境 -> 调工具/感知模块 -> 推理 -> 查记忆 -> 规划 -> 执行动作 -> 反思/更新经验
```

如果再加 V2V/V2X 通信，就是 cooperative / multi-agent driving。

典型组件：

- **Memory**：长期经验、规则、失败案例。
- **Tool use**：调用感知、预测、地图、搜索、碰撞检查等工具。
- **Reflection**：对失败决策做反思，更新经验。
- **Communication**：车车之间交换意图、风险、协商结果。
- **Negotiation**：多车让行、合流、会车、交叉口博弈。

代表：

- **Agent-Driver**：工具库、认知记忆、CoT 推理、任务规划、运动规划、自反思。
- **DiLu**：driver agent + memory + reasoning/reflection。
- **AgentsCoDriver**：多车 agent，包含 observation、reasoning、memory、reflection、communication。
- **DriveAgent**：多个专门 agent 进行传感器分析、因果推理和决策。
- **CoLMDriver**：LLM negotiation + intention-guided waypoint generator。
- **LangCoop**：用自然语言做多车通信。

### TalkingVehicles
- 时间：ICLR2025 投稿（OpenReview Submission 569）
- 拒绝 openreview
	- Decision：Reject
	- Review 分数：6 / 3 / 3 / 3，confidence：4 / 4 / 4 / 3
	- 正面评价：方向新，提出自然语言 V2V 协作驾驶问题、TalkingVehiclesGym 环境，以及 episode 后多车 debrief 的学习流程。
	- 主要质疑：自然语言相对人工通信协议的必要性不足；训练更像 prompt-agent 经验反思而非传统 ML；真实系统中的延迟、拥塞、多车规模化、非诚实/非合作车辆、环境手工规则和 captioner 依赖没有充分验证。
- 结构

TalkingVehicles 的核心不是“VLM 直接看图开车”，而是把 **V2V communication** 变成自然语言协议，让多个 LLM driving agents 在 CARLA / TalkingVehiclesGym 里通过说话共享盲区信息或协商路权。
```text
CARLA / TalkingVehiclesGym
        -> rule-based partially-observable captioner
        -> 每辆车的文本观测 + task/goal + traffic rules + received messages
        -> LLM policy
            -> CoT reasoning
            -> JSON 决策：message + high-level command
        -> MQTT V2V broadcast
        -> atomic controller 执行 go / stop / slow down / speed up / lane change
        -> 环境反馈：success / collision / stagnation / reward
        -> replay buffer
        -> post-episode debrief
            -> 采样关键失败/交互片段
            -> 多 agent 轮流复盘和提出 cooperative strategy
            -> 每个 agent 反思并更新 in-context knowledge
        -> 下一轮 self-play / evaluation
```

结构可以拆成四层：

- **环境层：TalkingVehiclesGym**
	- 基于 CARLA，接口接近 Gymnasium / PettingZoo。
	- 用 MQTT 模拟 episode 内 V2V 通信。
	- 支持异构 agent：language agent、sensor agent、human agent、behavior agent。
	- 场景分两类：Cooperative Perception（overtake、red light violation、left turn yield）和 Negotiation（overtake、highway merge、highway exit）。
- **感知到语言层：partial-observable captioner**
	- 为 language-only LLM agent 把局部可见传感器和规则信息转成文本 observation。
	- 仍保留 partial observability：agent 不能直接看到被遮挡区域，只能靠其他车发消息补盲。
	- 这也是论文的一个局限：感知不是端到端 VLM，而是理想化/规则化 captioner。
- **Agent policy 层：LLM 生成消息和高层命令**
	- Prompt 输入：任务目标、交通规则、文本观测、最近消息对话、cooperative strategy、learned knowledge。
	- LLM 先做 CoT reasoning，再输出结构化 JSON。
	- 输出分两部分：给其他车的自然语言 message，以及 atomic driving command。
	- atomic command 只覆盖高层动作：go、stop、slow down、speed up、change left/right lane；低层 throttle / brake / steering 由 atomic controller 处理。
- **学习层：LLM+Debrief**
	- Episode 中：agent 一边通信一边执行，消息会进入下一步 observation。
	- Episode 后：环境返回语义反馈，例如碰撞、超时、停滞、成功。
	- Replay buffer 保存 observation、reasoning、message、command、其他车辆反应和反馈。
	- Debrief 时采样碰撞前、停滞、强交互片段，让多车轮流讨论失败原因和未来协作策略。
	- 讨论结果被每个 agent 总结为长期 in-context knowledge，下一轮决策时作为 prompt memory 使用。

实验设计上主要比较：
- **Silent vs Comm**：没有通信的 LLM 往往更保守；有自然语言通信后，部分场景成功率提高，但也可能因为过度自信而增加碰撞。
- **Reflection / Reflection+RAG / Debrief**：单车反思和 RAG 不稳定；LLM+Debrief 通过多车集中复盘再分散执行，更适合学习协作策略。
- **Coopernaut**：作为 LiDAR cooperative perception 参考，不是同一类方法，因为 Coopernaut 传的是中间传感器表示，不是自然语言。
```text
主分类：B6. Agentic / Cooperative Driving
副分类：B2. Prompt-based / Tool-based Driving Planner
不是：B4 强 VLA Driving Model / B5 Driving Foundation Model
补充标签：natural-language V2V、self-play、LLM+Debrief、CTDE-style debrief、CARLA、MQTT、atomic actions
```
- 动机：
	- 开放性：传统优势仅限于使用相同学成环境表示和通信语言的车辆，限制了具有不同表示或语言的车辆更广泛参与，也使得人类驾驶员仍然只能依赖本地感知，无法获知协作努力的存在。

### LangCoop

LangCoop 的核心是把多车通信压缩成自然语言消息。它不是直接传图像或完整特征，而是用语言打包关键信息，降低通信带宽，并提高异构 agent 之间的信息兼容性。

![[图片/LangCoop-Figure1-Framework.png|700]]

### CoLMDriver

CoLMDriver 把 LLM-based negotiation 接到实时控制。它包含并行驾驶管线：一个 LLM 协商模块持续更新合作策略，另一个 intention-guided waypoint generator 把协商结果转成可执行 waypoints。
