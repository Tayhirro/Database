## 通用轨迹预测流程（第一性原理版）
> 先别背模型名字：轨迹预测本质是学一个条件分布 `p(Y | X, C)`，把“过去 + 场景上下文”映射成“未来的一组可能轨迹”。
> - `X`：历史观测（你真正看得到的）
> - `C`：上下文/约束（地图、规则、信号灯、车道拓扑、其他 agent）
> - `Y`：未来轨迹（你想要输出的）

## 补充概念：低秩（Low rank）与 SVD（截断）
> 所属知识：线性代数 / 数值线性代数（矩阵分解与矩阵逼近）。

### 3) “低秩”在这里怎么体现？为什么和 SVD 有关？
- “低秩/近似低秩”的一种表述：矩阵的奇异值序列 $\{\sigma_i\}$ 快速衰减，使得存在较小的 $r$，令用秩不超过 $r$ 的矩阵就能把 $X_c$ 逼近到较小误差。
- 与 SVD 的关系：截断 SVD 给出常见范数下的最佳秩-$r$ 近似（Eckart–Young–Mirsky）。

### 3.1 低秩的 SVD 解释（截断）
设 $X_c = U_c\Sigma_cV_c^\top$ 为 $X_c$ 的 SVD，取前 $r$ 个奇异值/奇异向量得到
$$
X_{c,r}=U_{c,r}\Sigma_{c,r}V_{c,r}^\top,
\qquad \operatorname{rank}(X_{c,r})\le r,
\qquad X_c \approx X_{c,r}.
$$
常用误差写法（奇异值按降序排列）：
$$
\lVert X_c - X_{c,r}\rVert_2=\sigma_{r+1},\qquad
\lVert X_c - X_{c,r}\rVert_F^2=\sum_{i>r}\sigma_i^2.
$$

- 秩（rank）：[[math/线性代数/modules/Rank]]
- 低秩近似与截断 SVD：[[math/线性代数/modules/LowRankApproximation]]

### 0. 任务
- 预测对象：ego 还是全场景多 agent（marginal vs joint）。
- 时间：观测长度 `T_obs`，预测长度 `T_pred`，采样频率。
- 输出形式：单条轨迹（deterministic）还是多模态 `K` 条/一个分布（stochastic）。
- 坐标系：全局坐标 / ego 坐标 / lane 坐标（这决定模型学的难易度）。

### 1. 数据输入
- 动态：每个 agent 的历史状态序列（`(x,y)`，可选 `v,a,yaw` 等）。
- 静态：HD Map（车道中心线、可行驶区域、交叉口拓扑、信号灯状态等）。
- HD Map 表示方式（决定后续 encoder/交互的 token 化形态）：
  - raster（BEV 栅格图）：把地图/可行驶区/车道线渲染成图像通道，用 CNN 提特征；优点是实现直接、适配感知特征融合；缺点是分辨率-范围权衡、几何精度与拓扑先验弱。
  - vector（矢量/图）：把地图表示为稀疏的线/段/节点 token（常见 polyline / lane graph / roadgraph），显式保留几何与拓扑，便于做稀疏交互。
    - LaneGCN：lane segment 作为节点，中心线几何（点序列）编码成 node feature，再在拓扑边（pre/succ/left/right/merge...）上做图消息传递；交互阶段常用相对位置/朝向等作为 edge feature。
    - VectorNet / MTR：polyline 作为 token，先对每条 polyline 的点序列做内部聚合得到 `X ∈ R^{N×D}`，再在 polyline 间做图/注意力交互（`E` 多由 `kNN/半径` 构建）。
    - PGP：roadgraph 采样一串节点（每个节点带 `(x,y,heading)` 等几何属性 + 语义指示位，如 stop/crosswalk），后续在该图上做传播/规划约束相关的推理。
- 场景：agent 类型、交互关系、交通规则、天气光照等（可选）。

### 2. 预处理与对齐
- 统一坐标与尺度：平移到最后一帧、旋转到 ego 朝向、单位归一化（减少学习负担）。
- 处理可变数量：每帧 agent 数不定，通常用 padding + mask，或用 set/graph 表达。
- 地图向量化：把 map 变成 polyline/roadgraph token（比 raster 更几何友好）。

### 3. 编码
- 轨迹编码：对每个 agent 的历史序列做编码，得到 embedding（RNN/Transformer/MLP 都行，本质是提取“运动状态 + 意图线索”）。
- 地图编码：对车道/路口等 map token 编码，得到可被查询的 map memory。
- 输出：一份场景上下文表示 `H`（可能是 `[A,T,D]` 的张量，也可能是图的节点特征）。

### 4. 交互建模
- 第一性原理：未来不是一个人自己决定的，`Y_i` 依赖 `Y_j`（避让、并线、抢道），所以要让表示里出现 “谁影响谁”。 
- 交互建模可以拆成 4 个正交要素：`V`（token/节点语义）、`E`（邻接/掩码）、`φ`（聚合算子）、`schedule`（组织方式）。


  - #这里可能会交叉进行，比如map-only后agent-map
  -  `V`（把什么当作“可交互的实体”）
    - actor-only（纯 agent / social）：节点=agent，专注多车交互（例如 HiVT）。
    - map-only（纯地图图）：节点=map 元素（lane/segment/polyline 等），专注“可行驶结构先验”（很多 map encoder 属于这类）。
      - lane graph（拓扑先验）：节点=lane/lane segment，边=拓扑连通（pre/succ/left/right/merge...），强可行驶结构但依赖 HD map 质量（LaneGCN 等）。
        - **Case Study: LaneGCN**
          - **节点定义（Segment-level）**：LaneGCN 不直接用整条 centerline 做节点，而是将其切分为更细粒度的线段（segment）。节点 $i$ 对应 centerline 上相邻两点 $(p_{start}, p_{end})$ 构成的直线段。
          - **特征构造**：明确编码“形状（Shape）”和“位置（Location）”两类信息。
            $$x_i = \text{MLP}_{shape}(v_{end} - v_{start}) + \text{MLP}_{loc}(v_{center})$$
            其中 $v_{end}-v_{start}$ 捕获朝向与长度，$v_{center}$ 捕获绝对位置。这种设计让特征兼具局部几何属性与全局位置感。
      - polyline token（VectorNet 范式）：节点=polyline（车道/边界/人行道/历史片段…），强调几何局部结构与可扩展性（VectorNet/TNT/MTR 等）。
      - lane graph vs polyline token（关键差异）：
        - **粒度差异**：
          - LaneGCN：**Segment-level**（线段级）。分辨率更高，能捕捉曲率变化，但节点数多（一条车道对应多个节点）。
          - VectorNet：**Polyline-level**（整条线级）。一条折线聚合成一个 token，感受野更大，计算更稀疏。
        - lane graph：`E` 由 HD map 拓扑给定（typed/directed），强调“可行驶可达性”。
        - polyline token：`V` 更通用（任意线状几何/轨迹片段），`E` 常由几何 `kNN/半径` 动态构建，强调“几何相关性/局部结构”。
        - 形状直觉：两者的几何输入常是“N个点（每个点表示一个线段）”`P ∈ R^{N×C}`，但做图消息传递时通常更新的是“每条线一个向量”`X ∈ R^{N×D}`（先对点序列编码/池化到 `D` 再在图上迭代）。
        - tensor 例子（同样 `N`，但 `E` 来源不同）：
          - lane graph：`X_lane ∈ R^{N×D}`，`edge_index_topo = [[0,1,2,3],[1,2,3,2]]`（successor/merge 等），可配 `edge_type`（succ/left/right/merge...）。
          - polyline token：点序列 `P ∈ R^{N*C}` → polyline encoder 得 `X_poly ∈ R^{N×D}`；
    - actor+map（异构图）：节点=agent ∪ map 元素，显式建 actor-map 边让道路几何/规则调制交互（例如 LaneGCN 的 actor-lane 消息流；MTR 解码时按轨迹收集 map polylines 再 cross-attn）。  
    - 当然可以交互进行



  - `E`（决定“谁影响谁”，也是稀疏性的来源）
    - 几何近邻：半径 `r` / Top-K `kNN`（最常见、稳定，但可能漏掉远处关键交互）。
    - 规则/语义近邻：同/相邻车道、优先权、潜在冲突区、TTC 等（更可解释，但更依赖启发式）。
    - 拓扑近邻：显式道路连通（lane graph 的 pre/succ/merge/split…）。
    - 静态 vs 动态：静态 `E` 只用当前帧/一次建边；动态 `E` 每步/每层重建（更贴合交互随时间变化，但更贵也可能更不稳定）。
    - query-条件的 `E`：解码阶段按“当前假设轨迹/目标”选相关 map token（例如 MTR 的 dynamic map collection）。


  - `φ`（给定 `E`，邻居信息如何融合进来）
    - 经典 GNN：GCN/MPNN/EdgeConv 等（显式消息函数 + 聚合）。
    - 注意力型聚合：GAT / sparse self-attn（本质就是“在 `E` 上做加权求和”）；全连接 self-attn 只是 `E` 取全连接的特例。
    - edge feature / type embedding：相对位置/速度、朝向差、距离、是否同车道/可达、拓扑关系类型等；很多“看起来一样的建图”差别其实在这里。
  - `schedule`（把复杂度拆开、让交互多次发生）
    - **交互粒度与时序调度**（关键区分点）：
      - **分段串联（Summary-level / Sequential）**：先对每个 agent/地图元素做时间编码（GRU/CNN/Pooling），压成一个向量（Embedding），再在这些向量之间做空间交互。
        - 代表：PGP, LaneGCN。
        - 优点：计算便宜（交互发生在 $A$ 维度，而非 $A \times T$），结构清晰。
        - 缺点：丢失了“未来第 t 秒发生交互”的细粒度时序对齐信息（Late interaction）。
      - **交替堆叠（Token-level / Interleaved）**：保留时间维度 $T$，在编码器层间交替进行“时间维更新”和“空间维交互”。
        - 代表：Scene Transformer, AgentFormer, HiVT。
        - 优点：能捕捉动态的时空依赖（Early interaction）。
        - 缺点：显存/计算开销大（$O(A \cdot T)$ 或 $O(A^2 \cdot T)$）。
    - **Case Study: PGP (Prediction via Graph-based Policy)**
      - 属于典型的**分段串联**模式（先时间，后空间）。
      - **$V$**：
        - Map 节点：Lane graph node（每个节点内的几何序列经 GRU 编码成向量）。
        - Agent：周车/行人历史轨迹经 GRU 编码成 Motion Vector。
        - **关键点**：时间维在这一步被 GRU “终结”了，后续交互全是基于这个 Summary 向量的。
      - **$E$**：
        - Agent $\to$ Node：几何近邻（Attention）。
        - Node $\leftrightarrow$ Node：车道拓扑边（GNN）。
      - **$schedule$**：Temporal (GRU) $\to$ Spatial (Agent-Node Attn) $\to$ Topological (Node-Node GNN)。它没有在时间步层面上做交互，而是把“这个车过去怎么走的”作为一个整体特征去影响“这条路”。
    - factorized/分解：时间维 vs agent 维交替建模（把 `O(A^2T^2)` 拆成 `O(A^2T + AT^2)` 一类）。
    - hierarchical：先 polyline 内部聚合（subgraph），再 polyline 间全局/稀疏交互（global）。
    - iterative refinement：用 query 反复“读 context→更新预测→再读”（例如 MTR 解码器）。
  - `attention vs graph`：`graph` 侧重 `E`（连谁/可达性），`attention`/`GNN` 侧重 `φ`（怎么聚）；例如 MTR 的 `kNN` local self-attn 可视为在 `E` 上做一层 GAT。

#### 4.x 补充：文献中“社交交互”常见实现形态
- 社交池化（Social-LSTM 范式）：用局部网格/社交张量 + pooling 汇聚邻居隐状态，属于“手工邻域 `E` + 固定聚合 `φ`”，不要求显式 GNN。见 [[轨迹预测/modules/社交池化]]。
- 注意力交互：用可学习权重对邻居做加权汇聚，可视为“学习得到的边权”。见 [[轨迹预测/modules/注意力交互]]。
- 图交互建模（GNN）：节点=智能体、边=交互关系，在边上做消息传递/聚合。见 [[轨迹预测/modules/图交互建模]]。
- 上级抽象：交互建模统一接口与 `V/E/φ` 分解见 [[轨迹预测/modules/智能体交互建模]]，分支导航见 [[轨迹预测/索引]] 与 [[轨迹预测/概念图]]。

### 5. 多模态来源
- 第一性原理：同一段历史 `X` 对应多个合理未来（意图不可观测 + 规划选择），所以需要表示 `p(Y|X,C)` 的"多峰"。
- 常见做法（按"多模态从哪来"分类）：
#### 5.1 Latent 变量法（显式建模意图/模式的隐变量）
- **连续 latent（CVAE 系）**：
  - 代表：AgentFormer, MTR 等
  - 思路：引入连续隐变量 `z ~ N(0,I)`，表示"意图/目标/驾驶风格"等不可观测因素
  - 训练：后验 `q(z|Y,X)` 看得到未来，优化 ELBO（重建 + KL 散度）
  - 训练：后验 `q(z|X)` 看不到未来，但对齐`q(z|Y,X)`
  
  - 推理：从先验 `p(z|X)` 采样 `K` 次，每次解码一条轨迹
  - 优点：概率框架完整，可以学到连续的意图空间
  - 缺点：KL 塌缩风险、采样质量依赖 prior 训练好坏、需要较多采样才能覆盖多样性
- **离散 latent（可学习的 mode seeds）**：
  - 代表：AutoBot, MultiPath++
  - 思路：decoder 里维护 `K` 组可学习的 seed/query embeddings `{Q_1,...,Q_K}`，每个 `Q_i` 对应一个离散的"mode"
  - 训练：可以精确计算 `p(Y|X) = Σ_k p(Y|Z=k,X)p(Z=k|X)`（对离散 latent 求和），用 EM 风格优化
  - 推理：一次 forward 直接并行解码出 `K` 条，每条带概率
  - 优点：模式数固定、推理快（不需要重复采样）、可以直接优化 log-likelihood
  - 缺点：`K` 固定、模式语义不可控、可能出现"mode collapse"（某些 seed 不被激活）

$$p_\theta(Z = k \mid X, Y) = \frac{p_\theta(Z = k \mid X) \, p_\theta(Y \mid X, Z = k)}{\sum_{j=1}^{c} p_\theta(Z = j \mid X) \, p_\theta(Y \mid X, Z = j)}$$

#### 5.2 多候选集法（直接输出 K/F 条轨迹）
- **并行解码多个 future**：
  - 代表：Scene Transformer, MTR，LaneGCN
  - 思路：解码器直接扩展一个 "future 维度"，输出 `[F, A, T, D]` 或 `[K, T, D]`，每个 future 配一个概率头   输入 MTR：K,2    SceneTransforme：历史轨迹
  - Scene Transformer（tensor 级流程，scene-centric + factorized attention）：
    - 输入：agent 历史轨迹/状态 → embedding 得到 `H0 ∈ R^{A×T_obs×D}`；road graph polylines → PointNet 得到 `R ∈ R^{G×D}`；同时构造 mask（哪些 agent/time 位置可见/要预测）。
    - 编码：交替做 factorized self-attn（time-attn 沿 `T`、agent-attn 沿 `A`）更新 `H`；中间插入 `H ↔ R` 的 cross-attn 融合地图；并加入额外的“均值聚合”行/列，使内部表征变为 `[A+1, T+1, D]`（用于全局/概率头）。
    - 解码（本质是 masked modeling 的“补全”，不是自回归 rollout）：
      - 先把“需要预测的未来时刻”在输入里用 mask/占位 embedding 标出来（模型看到：历史可见 token + 未来 masked token）。
      - masked token 的“初始化”并不是空的：论文实现细节里写到 hidden 时会把该 timestep 的输入特征（位置/速度/type/state 等）置 0，仅保留 time embedding（线性递增的时间值）和 hidden indicator；再过输入 embedding MLP 得到该位置的 `x`，因此 `q/k/v = W·x` 能正常计算。只有 padding 的位置才会被 attention 彻底屏蔽（权重置 0）。
      - 将编码后的场景张量（含 `[A+1, T+1, D]` 的全局 token）复制 `F` 份得到 `H_f ∈ R^{F×(A+1)×(T+1)×D}`，并给每个 `f` 拼一个 `F` 维 one-hot（Appendix: `D → D+F`）后过一个小 MLP 映射回 `D`，从而让不同 future 分支有不同的初始“身份标识”。
      - 对每个 `f` 的张量，过 decoder 堆叠层：factorized self-attn（沿 `T` 的 time-attn 是双向全连接注意力，不做“只能看过去”的下三角 causal mask；再沿 `A` 做 agent-attn）+ road graph cross-attn（Q 来自 agent tokens，K/V 来自 road graph embeddings）+ FFN；无 causal mask，因此一次 forward 同时输出所有 `T_pred`。
      - 例子（未来轨迹预测）：若 `T_obs=1`、`T_future=2`，则先构造 token 网格 `X ∈ R^{A×(1+2)×D}`，其中 `X[:,0,:]` 是观测到的当前/历史，`X[:,1,:], X[:,2,:]` 用同一个 mask/占位 embedding；再加“额外 agent/time”得到 `X' ∈ R^{(A+1)×(1+2+1)×D}`。time-attn 时每个 `X'[a,·,:]` 都会在这 `4` 个 time token 上做全连接注意力，因此未来两个 mask token 会互相 attend、也会 attend 历史 token（但不会偷看 GT，因为 GT 没作为输入 token 提供）。
    - 输出：回归头 MLP 输出 `Y_hat ∈ R^{F×A×T_pred×7}`（位置/朝向/不确定性等参数）；概率头从每个 future 的全局 token 得到 logits `∈ R^{F}`，softmax 得到 `p_f`（训练常用 best-of-F/WTA 或 joint/marginal 两套 loss 切换，细节见后文 Scene Transformer 章节）。
  - MTR（Motion Transformer：motion query pair + 迭代 refinement）：
    - 输入（vectorized polylines）：agent 历史 `A_in ∈ R^{N_a×t×C_a}`、map polylines `M_in ∈ R^{N_m×n×C_m}`（都转到 agent-centric 坐标系）。
    - Polyline encoder（PointNet-like）：`A_p = pool(MLP(A_in)) ∈ R^{N_a×D}`，`M_p = pool(MLP(M_in)) ∈ R^{N_m×D}`。   #提取agent，line级别feature，逐点MLP与pooling

    - Transformer encoder（local self-attn）：把 `G0=[A_p;M_p]` 拼起来，对每个 token 只和 `kNN` 邻居做 self-attn（keys/values 取邻居），得到 scene context（`A_past`、`M`）。 #a_past为G[:len(A_p)]  #q_agent--kv信息交互
      - 图视角：`V` 是所有 agent/map 的 polyline token，`E={(i,j) | j∈kNN(i)}`（按 agent 最新位置 / polyline center 的几何距离取近邻）；这层 local self-attn 就是在 `E` 上做消息传递（≈GAT）。

    - Dense future prediction（辅助任务）：用 `A_past` 回归所有 agent 的单模态未来 `S_{1:T} ∈ R^{N_a×T×4}`（位置+速度），再把 `S_{1:T}` 重新用 polyline encoder 编成 `A_future ∈ R^{N_a×D}`，与 `A_past` concat 后过 MLP 得到增强后的 agent context `A`（把“未来交互”信号显式注入）。

    - Transformer decoder（并行 `K` 模态 + 迭代 refinement）：
      - 先准备 `K` 个“静态意图点” `I ∈ R^{K×2}`（k-means 聚类 GT endpoint 得到）；由它生成 static intention query `Q_I=MLP(PE(I)) ∈ R^{K×D}`。
      - 初始化 query content `C^0=0 ∈ R^{K×D}`；dynamic searching query 初始也来自意图点（后续每层用上一层预测轨迹终点更新：`Q_S^{j+1}=MLP(PE(Y_T^j))`）。
      - 第 `j` 个 decoder layer：先用 `Q_I` 做 queries 之间的 self-attn（区分不同 mode、共享信息）；再用 `Q_S^j` 做 cross-attn 去读 agent context `A`，以及通过 dynamic map collection 收集“沿当前预测轨迹附近”的 `L` 条 map polylines（trajectory-specific map feature）再 cross-attn；融合后得到 `C^j`，并用 head 输出 `Z^j ∈ R^{K×T×6}` 的 GMM 参数（每个时间步一个 mixture），轨迹 `Y^j` 可取各 mode 的 GMM 均值。
        - 图视角：cross-attn 可看作 query token 与 context token 的二部图读出；dynamic map collection 相当于在 query-map 边上再施加一个稀疏 `E_{Q→M}`（只连到与当前预测轨迹相关的 map token）。
    - 训练：aux 的 L1 回归 + 每层 GMM NLL；mode 分配用 hard assignment（按 `I_k` 和 GT endpoint 的距离选一个最接近的 `k` 当正样本），类似 WTA 但“先用意图点做匹配”。
  - 训练：用 best-of-K / Winner-Takes-All (WTA)，只对最接近 GT 的那条回传梯度（避免惩罚多样但合理的预测）
  - 推理：一次 forward 得到 `K` 条轨迹 + 概率，直接输出
  - 多模态来源：
    - 方式1：通过不同的 learnable query embeddings 区分（类似离散 latent）
    - 方式2：通过 attention 机制自然分化（不同 query 会 attend 到不同 context）
    - 方式3：结合目标点采样（Goal-conditioned），每个 goal 对应一个 future
  - 优点：端到端、推理快、符合评估指标（minADE@K）
  - 缺点：训练时需要处理"匹配问题"（哪条 future 对应 GT）、可能出现模式重复

#### 5.3 采样式法（隐式多模态 + 后处理）
- **目标/路径采样 + 条件解码**：
  - 代表：TNT (Target-driven), DenseTNT, LaneGCN traversal
  - 思路：
    - 第1步：在空间或 lane graph 上采样 `M` 个候选目标/路线（lateral 多样性）
    - 第2步：对每个目标 `g_k`，条件解码一条轨迹（可选：再加连续 noise 控制 longitudinal 多样性）
    - 第3步（可选）：对 `M` 条聚类/NMS/打分，选出最终 `K` 条
  - 例子：
    - TNT：先预测目标点集合（在可行驶区域 grid 上分类），再条件回归轨迹
    - LaneGCN traversal：在 lane graph 上 roll-out 路线，每条路线解码一条轨迹
  - 优点：多模态来源清晰（路线级差异 vs 速度级差异分离）、可解释性强
  - 缺点：需要设计采样策略、两阶段训练/推理复杂度高

- **噪声注入采样**：
  - 代表：STAR, 部分 Diffusion-based 方法
  - 思路：解码时把随机噪声 `ε ~ N(0,I)` 与 context embedding 拼接，通过不同噪声产生不同未来
  - 训练：通常配合 best-of-K loss（回归式）
  - 推理：采样 `M` 次噪声 → 得到 `M` 条轨迹 → 聚类/去重 → 输出 `K` 条
  - 优点：实现简单、灵活
  - 缺点：多样性质量依赖噪声维度和解码器容量、需要后处理去重

#### 5.4 扩散模型法（Diffusion-based）
- 代表：MotionDiffuser, Leapfrog Diffusion
- 思路：把轨迹预测当作"从噪声逐步去噪到干净轨迹"的过程
- 训练：学习逆扩散过程 `p(Y_{t-1}|Y_t,X,C)`
- 推理：从纯噪声 `Y_T ~ N(0,I)` 开始，逐步去噪 `T` 步得到轨迹
- 多模态：天然支持采样（每次去噪可以采样不同路径）
- 优点：理论框架成熟、生成质量高、多样性好
- 缺点：推理慢（需要多步去噪）、训练复杂度高

#### 5.5 总结对比表

| 方法类别 | 多模态来源 | 推理方式 | 代表方法 | 优点 | 缺点 |
|---------|----------|---------|---------|-----|------|
| 连续 latent (CVAE) | 采样 `z~N(0,I)` | 重复采样 `K` 次 | AgentFormer, MTR | 概率完整、连续空间 | KL 塌缩、需多次采样 |
| 离散 latent (seeds) | `K` 个可学习 query | 一次解码 `K` 条 | AutoBot, MultiPath++ | 快速、精确 likelihood | 模式固定、可能 collapse |
| 并行多 future | query embeddings | 一次解码 `K` 条 | Scene Transformer | 端到端、快速 | 需处理匹配、可能重复 |
| 目标/路径采样 | 空间/graph 采样 | 两阶段解码 | TNT, LaneGCN | 可解释、清晰 | 两阶段复杂、依赖采样 |
| 噪声注入 | 随机噪声 `ε` | 采样+聚类 | STAR | 简单灵活 | 质量依赖设计、需去重 |
| Diffusion | 去噪过程 | 多步采样 | MotionDiffuser | 质量高、多样性好 | 推理慢、训练复杂 |

#### 5.6 实践建议
- **快速 baseline**：并行多 future（Scene Transformer 风格）或离散 latent（AutoBot 风格）
- **高质量多样性**：CVAE + 好的 prior，或 Diffusion（代价是推理慢）
- **可解释性优先**：目标/路径采样（TNT/LaneGCN 风格）
- **轻量级**：噪声注入（但要做好聚类去重）

### 6. 解码（把表示变成未来轨迹）
- 两个主流范式（你以后看论文就按这条分）：
  - autoregressive：一步一步预测 `t=T_obs+1..T_obs+T_pred`，每步可重建交互图/更新状态（优点是“闭环”，缺点是误差累积）。
  - non-autoregressive：一次性输出整段未来（优点是快、并行；缺点是要自己处理时间一致性）。
- 输出头（你最终要的东西）：
  - 回归点序列：直接输出 `(x_t,y_t)`。
  - 概率分布：输出每步高斯参数/混合分布参数，用 NLL 训练（更像在学 `p(Y|X,C)`）。

- 补充：采样式/隐式多模态解码（仍然可以归到 non-autoregressive + 回归点序列）
  - 思路：不显式输出 `p(Y|X,C)` 的参数，而是“采样→得到很多轨迹→再挑 K 条代表”（聚类/NMS/去重）。
  - 多模态来源常见拆法：`(离散的路线/目标采样)` 负责 lateral（走哪条路），`(连续 latent/噪声)` 负责 longitudinal（加速/刹车/速度剖面）。
  - 训练常配：best-of-K / WTA（`min_k` 的回归损失），避免惩罚多样但合理的预测。
  - 例：Deo et al., 2021《Multimodal Trajectory Prediction Conditioned on Lane-Graph Traversals》
    - 先用离散 policy 在 lane graph 上 roll-out，得到一条 traversal（节点序列）；
    - decoder 用 multi-head attention 只在该 traversal 的节点上聚合上下文，得到 route context `C_k` （复杂预处理）；
    - 采样 `z_k ~ N(0,I)`，拼接 `concat(h_motion, C_k, z_k)`，用 MLP 一次性输出整段未来轨迹 `τ^k_{1:t_f}`（非自回归点序列回归）；
    - 推理时可并行采样很多条，再用 K-means 得到最终 `K` 条 mode；训练用 `L_reg = min_k ADE(τ^k, τ_gt)`。

### 7. 训练目标（模型到底在优化什么）
- 覆盖导向（多模态常用）：best-of-K / minADE@K 对齐评估指标，让 `K` 条里至少有一条贴 GT。
- 概率导向：最大化对数似然 `log p(Y|X,C)`（有显式分布输出时更干净）。
- 多样性与可行性约束：防止 `K` 条塌缩、约束车道/碰撞/动力学（有的用正则，有的用后处理/约束解码）。

### 8. 推理与输出给规划（落地时最容易踩坑）
- 你真正要给下游的是：`K` 条候选轨迹 + 每条概率/置信度 + 可行性标记（是否越界/碰撞风险）。
- 如果只给一条“最可能”，规划会被你骗；如果只给一堆“很发散”，规划会崩。

### 9. 把这套流程映射到你这页的 4 个方法（速记）
- AgentFormer：latent（CVAE）负责多模态；Transformer 负责时间+社交交互；解码自回归。
- Scene Transformer：scene tensor + factorized attention；一次输出 F 个 futures（并行解码）+ best-of-F 训练。
- AutoBot：离散 latent = 多组 learnable seeds（mode）；精确/近似 EM 形式做 likelihood；解码非自回归、整段输出。
- STAR：图上的 TGConv 做空间交互 + temporal transformer；加噪声做多模态；自回归 roll-out + 外部记忆保时间平滑。

## AgentFormer（Agent-Aware Transformer + CVAE）
> PDF：[[轨迹预测/论文/agentawaretransformer.pdf]]

### 1. 定位
- 面向多智能体（行人/车辆）的**随机（stochastic）多模态轨迹预测**：显式用 CVAE latent 表达意图不确定性，同时用 Transformer 建模时间演化与社交交互。

### 2. 核心表示
- 把多智能体轨迹按 `(agent, time)` 展开成序列 token（论文描述为 flatten across time & agents），再加时间编码得到时序表示。

### 3. 交互建模（Agent-Aware Attention）
- 关键点：注意力里**显式保留 agent 身份**。
- 做法：对“同一 agent 的 token”与“其他 agent 的 token”使用两套不同的 `Q/K` 投影（intra-agent vs inter-agent），并用 `M_ij = 1(i mod N = j mod N)` 这样的 mask 判定 query/key 是否同 agent。
- 结果：模型能在推断某个 agent 某一时刻时，直接 attend 到**任意 agent 的任意历史时刻**，同时不丢失“这是谁的轨迹”。

![[轨迹预测/img/image.png]]

### 4. 地图/环境融合
- 可选引入语义地图 `I`：对每个 agent 做旋转对齐 + crop，CNN 提取视觉特征 `v_n`，再与每个时间步的轨迹 token 拼接进入编码器。

### 5. 多模态来源（CVAE latent intent）
- 为每个 agent 引入 latent `z_n` 表达“意图/目标”等不可观测因素。
- 训练：用 posterior `q(z|Y,X,I)`（看得到未来 `Y`）做推断，优化 ELBO（重建项 + KL）。
- 推理：从 prior `p(z|X,I)` 采样，重复采样得到多条未来（K samples）。

### 6. 解码方式（Autoregressive Future Decoder）
- future decoder 以自回归方式逐步生成 `y_{t+1}`：把当前已生成的轨迹片段与 `z` 结合，再与历史上下文特征交互，循环 `T` 步得到完整未来。

### 7. Loss（ELBO + Trajectory Sampler）
- CVAE 的主损失是负 ELBO（论文 Eq. (7)）：`L_elbo = -E_{q(Z|Y,X,I)}[log p(Y|Z,X,I)] + KL(q(Z|Y,X,I) || p(Z|X,I))`。
  - 直觉：第一项逼近 GT 未来（重构/似然），第二项约束 latent 不要偏离 prior（可采样性/可泛化）。
  - 重要细节：虽然 `p/q` 写成对 agent 因子分解，但它强调 latent `Z` 的推断与 `p(Y|Z,·)` 的生成是“全体 agent 联合”的（一个人的 `z_n` 会影响别人的轨迹生成）。
- trajectory sampler 的损失（论文 Eq. (9)）用于“更好地采 K 条”：
  - `L_samp = min_k ||Y_hat^(k)-Y||^2 + sum_{n=1}^N KL(r(z_n^(k)|X,I)||p(z_n|X,I)) + (1/(K(K-1))) * sum_{k1!=k2} exp(-||Y_hat^(k1)-Y_hat^(k2)||^2 / sigma_d)`。
  - `min_k` 覆盖：K 条里至少有一条贴近 GT；`KL` 约束：采样 latent 仍保持 plausible；`diversity`：惩罚样本彼此太相似。
  - 训练方式：训练 sampler 时冻结 CVAE 模块；推理阶段用 sampler 产生 `Z^(1..K)` 来替代“直接从 prior 随机采样”。

### 8. 特别内容（Trajectory Sampler 的“更像 GT 覆盖”的 K 采样）
- 额外训练一个 sampler 专门生成 `Z^(1..K)`，常能让 `K` 条预测更“多样”且更接近 `minADE@K / minFDE@K` 的评估方式（覆盖导向）。

### （补充）一条“流水线”记忆（和你现有笔记对齐）
- 训练（CVAE）：`(X, 可选 I)` →（可选：Semantic Map CNN 得到 `v_n` 并拼到轨迹 token）→ Time Encoder → AgentFormer Encoder 得到历史特征 `C` → Posterior `q(Z|Y,X,I)` → 采样 `Z` → 自回归 future decoder 得到 `Y_hat` → 优化 `L_elbo`。
- 推理（prior 采样）：`(X, 可选 I)` → `C` → Prior `p(Z|X,I)` → 采样 `Z^(1..K)` → 解码得到 `Y_hat^(1..K)`。
- 推理（trajectory sampler）：`(X, 可选 I)` → `C` → sampler（对 `C` 做 agent-wise pooling + MLP，生成每个 `k` 的 Gaussian 采样分布 `r(z_n^(k)|X,I)`）→ 采样 `Z^(1..K)` → 解码得到 `Y_hat^(1..K)`。
- `K`：一次输出/采样的候选 future 数；每个 `k` 对应一组全场景 latent `Z^(k)={z_n^(k)}` 与对应的多智能体未来 `Y_hat^(k)`（常配合 `minADE@K / minFDE@K` 评估）。

## Scene Transformer（Scene-centric + Factorized Attention + Masked Modeling）
> PDF：[[轨迹预测/论文/Scenetransformer.pdf]]

![[轨迹预测/img/image2.png]]

### 1. 定位
- 面向自动驾驶的**场景级（scene-centric）联合预测**：在同一个模型里同时支持 marginal / joint 预测，并通过 masked 建模把“条件预测/目标条件预测”统一成补全问题。

### 2. 核心表示（Scene-centric Tensor）
- 输入/中间特征保持为 `Agent Features [A, T, D]` 的场景级张量（全局坐标系 + 位置编码）。
- 输出为 `F` 个候选未来：解码阶段扩展到 `[F, A, T, ·]`，同时给每个 future 预测概率（likelihood）。

### 3. 交互建模（Factorized Self-Attention）
- 维护场景级特征张量 `H ∈ R^{A×T×D}`，把一次“全局 self-attn”拆成两步交替做：
  - time-attn：对每个 agent 独立在时间维 `T` 上做 self-attn（`[A, T, D]` 内每一行沿 `T` 交互）。
  - agent-attn：对每个时间步独立在 agent 维 `A` 上做 self-attn（`[A, T, D]` 内每一列沿 `A` 交互）。
- Encoder 结构（对应图 `image2.png`）：
  - `(time-attn → agent-attn) × 3`（先沿时间交互，再沿智能体交互，重复堆叠）。
  - 加一个额外的 agent 维与 time 维（`[A, T, D] → [A+1, T+1, D]`），用于引入全局聚合/缓解论文提到的 identity symmetry。
  - 在上述张量上两次插入 `agents → roadgraph` 的 cross-attn（地图融合），其间再穿插 `(time-attn → agent-attn)` 更新场景特征。
- Decoder 里同样沿 time/agent 交替 self-attn（图中为 `×2`），但解码是并行的（先 tile 出 `F` 份候选再做注意力更新），不是自回归逐步生成。
- 模块形态上是典型 transformer-style 子层：attention 子层 + position-wise `MLP`（图中标为 `MLP`）；残差/归一化在结构图里未展开，但实现通常会配套。
- 复杂度上从对 `A*T` 的全注意力，变为沿 `T` 与沿 `A` 的两类注意力交替，整体随 `A`、`T` 扩展更友好。

### 4. 地图/环境融合（Road Graph Cross-Attn）
- cross-attn 融合道路信息
- 把 road graph / polyline 等地图元素编码成 `Road graph [G, T, D]`（静态/动态 road graph 作为 side information）。
- 用 cross-attention 让 agent 特征去 attend road graph，从而把道路拓扑/车道结构注入预测。

### 5. 多模态来源（“直接输出 F futures”）
- 以“多候选集合”的方式表示多模态：一次输出 `F` 条 future（每条对应一个候选未来）。

### 6. 解码方式（Parallel / Non-autoregressive decode）
- 解码阶段显式扩展 future 维度到 `[F, A, T, ·]`，并给每条 future 配一个概率/likelihood 头。

### 7. Loss（best-of-F + 分类）
- 回归：用 best-of-F / `reduce_min` 思想，对每个样本只回传与 GT 最接近的那个 future 的回归损失。
- 分类：配合概率头的分类损失，学习每条 future 的相对概率。

### 8. 特别内容（联合一致性 + Masked 建模统一任务）
- 联合一致性（Joint vs Marginal）：只需切换 `reduce_min` 的聚合顺序（先按 agent 聚合 vs 先按 future 聚合）即可在 joint/marginal 目标间切换。
- Masked 建模：用 mask 指示 `(agent,time)` 哪些输入可见/不可见，把 motion/conditional/goal-conditioned prediction 统一成“mask 掉一部分 → 模型补全”的同一个接口（类似 BERT）。

## AutoBot（Latent Variable Sequential Set Transformers / ICLR 2022）
> PDF：[[轨迹预测/论文/AutoBot.pdf]]

### 1. 定位
- 面向自动驾驶/通用“序列-集合（sequence of sets）”数据的**多模态轨迹预测**：把一个场景表示成 `M 个 agent` 的集合，随时间演化；输出多个 scene-consistent 的未来 mode。
- 同一套架构可做：ego 单车预测（AutoBot-Ego）或多车联合预测（joint prediction）。

### 2. 核心表示（Sequence of Sets Tensor）
- 把输入写成三维张量（论文图示）：特征 `K` × agent `M` × 时间 `t`，对每个 `(agent,time)` 位置/速度等做嵌入后进入 Transformer。
- 通过交替沿时间轴与 agent 轴做注意力，把 `A×T` 的全局依赖拆成可控的两个方向建模（和你总结 Scene Transformer 的 factorized 思路同源，但 AutoBot 的叙事是“set transformer on sequences of sets”）。

### 3. 交互建模（Temporal MHSA + Social MHSA 交替堆叠）
- Encoder：多层 interleaved MHSA，交替做
  - temporal attention：沿时间轴建模每个 agent 的动态依赖
  - social attention：沿 agent 轴建模交互
- 这种设计强调：对 agent 维的置换有明确分析（论文给了 permutation sensitivity 的讨论），并且比把所有 token 扁平化成 `A*T` 再做全注意力更省。

### 4. 地图/环境融合（Map as Context）
- 论文描述 decoder 会把 **encoded map** 与 encoder context 一起使用（把地图当作额外上下文输入给 decoder），用于约束可行驶区域/路口几何等。

### 5. 多模态来源（离散 latent / 多个 learnable seeds）
- 用离散 latent 变量实现多模态：decoder 里维护 `c` 组 learnable seed 参数矩阵 `Q_i`，每个 `Q_i` 对应一个 mode（可理解为离散 latent 的一个取值）。
- 每个 mode 会输出一条完整未来（通常还带一个概率/权重），从而构成条件混合模型（conditional mixture）。

### 6. 解码方式（Non-autoregressive decode 全未来）
- 和很多 transformer 预测器的自回归不同：AutoBot **一次 forward 就解码出整个未来 horizon**（每个 mode 一次解码），不需要逐步 roll-out 每个时间步。
- 输出头常见是每步一个二维高斯的参数（论文里用 `φ` 产生 bivariate Gaussian 参数），用于概率训练/不确定性表达。

### 7. Loss（精确 log-likelihood + posterior/prior 匹配 + 正则）
- 因为 latent 是离散的，论文强调可以**精确计算** `log p(Y|X)`（对 `Z` 求和），并用类似 EM 的形式写梯度：`∇ log p(Y|X) = Σ_Z p(Z|Y,X) ∇ log p(Y,Z|X)`。
- 训练时用 `q(Z)=p_{θ_old}(Z|Y,X)` 重写目标 `Q(θ,θ_old)=Σ_Z p_{θ_old}(Z|Y,X)[log p_θ(Y|Z,X)+log p_θ(Z|X)]`，并最小化 `KL(p_{θ_old}(Z|Y,X) || p_θ(Z|X))`（让 prior 能覆盖 posterior）。
- 额外有 mode entropy 正则（ME）：惩罚输出分布熵过大，避免某个 mode 变成“啥都不确定”的大方差解。

### 8. 特别内容（速度/可扩展 + 统一建模 ego/joint）
- learnable seeds 让推理更快（mode 维度上做少量重复解码），是它和很多 autoregressive/采样式生成器的关键差异点。
- 一个值得记的本质点：它把多模态做成“离散 latent + 条件混合”，而不是“连续 latent + ELBO”那套 CVAE 叙事。

## STAR（Spatio-Temporal grAph tRansformer / Pedestrian）
> PDF：[[轨迹预测/论文/STAR.pdf]]

### 1. 定位
- 面向行人轨迹预测的**时空图 Transformer**：用纯 attention 建模
  - 空间交互（人-人）作为图上的 message passing
  - 时间依赖（单人历史）作为序列 attention
- 主打点：在 ETH/UCY 等拥挤场景里，用更强的注意力替代“RNN + 简单社交池化”。

### 2. 核心表示（Graph Sequence）
- 每个时间步 `t` 是一张图 `G_t=(V_t,E_t)`：节点是行人，边通常按距离阈值/邻居集构造；节点特征是位置嵌入 `h_t^i`。

### 3. 交互建模（TGConv：Transformer-style Graph Convolution）
- 把 self-attention 解释成“全连接图上的消息传递”，再把它裁剪到邻居集 `Nb(i)`，得到 TGConv：
  - message `m_{j→i} = q_i^T k_j`，对邻居做 softmax 得到权重，再加权聚合 value `v_j`
  - 残差连接保持自身信息（论文公式里显式 `+ h_i`）

### 4. 地图/环境融合
- 无（STAR 是 pedestrian crowd 预测设定，不显式用 HD map）。

### 5. 多模态来源（噪声注入采样）
- 预测下一步位置时，把随机高斯噪声与 embedding 拼接输入一个 FC 层，通过不同噪声采样得到不同未来（论文明确写了用 random Gaussian noise 来 generate various future predictions）。

### 6. 解码方式（Autoregressive step-by-step + 动态重建图）
- 先预测 `t = T_obs + 1`，再把预测点加入历史作为下一步输入，循环 roll-out 直到 horizon。
- 每一步会按预测位置重建 `G_t`（距离小于阈值 `d` 的连边），让交互图随未来演化。

### 7. Loss（监督回归）
- 论文主要按 ADE/FDE 做评估；训练目标是把预测轨迹拟合到 GT（回归式监督），多样性来自噪声采样而不是显式概率 NLL。

### 8. 特别内容（External Graph Memory：时间一致性平滑）
- 外部可读写的图记忆 `M_{1:T}`：Temporal Transformer 读取历史 embedding 作为条件；encoder2 把输出写回记忆。
- 论文给了一个很“朴素但好用”的实现：read 直接取 `M_1..M_{t-1}`，write 直接用最新 embedding 覆盖；效果是让 embedding 在时间上更平滑，缓解 Transformer 把序列当 bag-of-words 带来的时间一致性问题。
